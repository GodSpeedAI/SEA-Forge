## Material changes and anchors

1. `REQ-C2-RANGE-005` now permits complete-empty only for an actually
   registered stream whose registered path is successfully checked as absent
   or zero-byte under the cooperative lock. `V-C2-RANGE-02` distinguishes this
   case from unregistered, unreadable, and corrupt history. ADR-008's bounded
   reader decision repeats that predicate and acceptance distinction.
2. `REQ-C2-RANGE-004` specifies the stream-identity binding as a
   field-specific domain-separated SHA-256 digest. `REQ-C2-RANGE-005` applies
   the same encoding to each exact cursor filter: distinct fixed ASCII domain
   tag, presence byte, checked unsigned-64-bit big-endian UTF-8 byte length,
   and exact bytes when present; absent uses its absent tag and zero length.
   The signed token carries the digests, not raw stream/filter strings, and
   recomputes and compares them against the requested exact identity before
   seek. ADR-008 mirrors these requirements. No ID grammar or normalization is
   added.
3. `REQ-C2-RANGE-004` requires the existing `getrandom::fill` source, startup
   refusal before accepting requests on entropy error, and immediate zeroizing
   of the local seed after signing-key construction with existing `zeroize`
   support. `V-C2-RANGE-01` adds the entropy-failure and seed-clearing
   acceptance vectors. ADR-008 records the same vectors and fail-closed start.
4. Traceability remains attached to the existing range requirements: RANGE-004
   maps to RANGE-01/03 and RANGE-005 maps to RANGE-01/02/03/LEGACY-01. RANGE-01
   now explicitly lists RANGE-004. No duplicate requirement or matrix ID was
   added; no unrelated traceability entry was changed.
