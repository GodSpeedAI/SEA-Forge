# C2 projected-facts in-tree writer enumeration recon

Date: 2026-10-08  
Scope: source-only inventory for `LiveSource` inputs consumed by `CaseList`, `CaseOverview`, `CaseHorizon`, `PendingApprovals`, and `RunsListForCase`. This is a bounded source inventory, not migration approval or proof that all writers participate in the proposed journal.

## Authority and view boundary

The accepted C2 spec requires an independent exhaustive writer audit before migration readiness (`.agents/specs/casework-live-cursor-v4-spec.yaml`, `REQ-C2-WRITERS-001`, `REQ-C2-JOURNAL-001..003`, `REQ-C2-EXTERNAL-001`, `V-C2-WRITERS-01`). Its current writer list is expressly a checklist, not proof. `apps/godspeed-casework-go/internal/projection/live.go:43-76` names the five reads in scope. Server view sources confirm their backing files: `crates/sea-forge-server/src/sfwp/case_views.rs:11-13,249-307,310-405`; `run_views.rs:22-30,391-506,777-833`; and `approvals.rs:15-17,220-251`.

The case views consume `cases/*/case.json`, case `plan.json`, and `case-events.jsonl`; case overview follows the case record's `run_ids` to settlement files. `run_views::list` discovers both `cases/*/runs/*` and `runs/*`, maps ownership only from `case.json` run IDs, then reads `trace.jsonl`, `settlement.json`, and the evidence-row count from `evidence.jsonl`. Approval listing folds `approvals.jsonl`. Thus a run directory or settlement alone does not establish case ownership, while changes to `run_ids` and each listed run file can change a projected row.

## Classification, locking, and limits

Federation import is not a producer for these five current views: CLI `commands/federation::import` authorizes `import_bundle` and calls `sea_forge_cell::import`, which stores under `imported/<cell-id>` (`crates/sea-forge-cli/src/commands/federation.rs:56-64`; `crates/sea-forge-cell/src/bundle.rs:174-178,270-290`). The current case/run view walkers enumerate `cases/*` and `runs/*`, not `imported/*`. Imported bundles are therefore outside this projection unless a separate adoption/copy path writes the projected locations. Manual, plugin, and out-of-tree filesystem writers are outside the in-tree inventory and explicitly unsupported by `REQ-C2-EXTERNAL-001` during live operation.

Existing locks are narrower than the required shared journal boundary. `LedgerStream::with_exclusive_lock` uses standard-library `File::lock()` for one `ledgers/<stream>/stream.lock` (`crates/sea-forge-ledger/src/types.rs:690-723`); the server's `.server.lock` is a server-lifetime lock (`crates/sea-forge-server/src/lib.rs:1092-1115`); and `ServerState::acquire_case_lock` is a Tokio in-process mutex (`lib.rs:343-375`). Searches for `fs2`, `FileExt`, `flock`, `lock_exclusive`, `lock_shared`, and `lockf` found no reusable cross-process C2 projection-lock helper. Standard-library file locking is present, but current locks do not coordinate CLI, CaseRunner, server, migration, all target files, and the proposed global journal as one operation.

The enumeration follows exact known view paths and direct writer/helper callers; it does **not** establish exhaustive participation. Generic filesystem APIs can write dynamically assembled paths, public CaseRunner APIs may have downstream consumers, and this search did not prove absence of indirect or runtime-generated writers. Nor does source presence prove journal participation, cross-process exclusion, or crash recovery. Treat the writer-inventory and migration-readiness requirements as open until the planned complete audit closes those gaps with participation evidence.
