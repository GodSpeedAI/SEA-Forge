# Case inventory fail-closed correction — source options

Date: 2026-10-06  
Status: documentation-only source options; no correction or approval released.

## Current behavior and contracts

- Rust `sfwp::case_views::list(root) -> CaseListResult` returns `{cases, unreadable}` (`crates/sea-forge-server/src/sfwp/case_views.rs:145-153,310-355`). Any `read_dir(root/cases)` error returns the empty default (`:314-317`); iterator errors are discarded by `flatten` (`:319`); `path().is_dir()` collapses metadata errors to false and non-UTF-8 names are skipped (`:320-325`). For a known directory, `read_case` maps every metadata and file-read error to `CaseViewError::NotFound` (`:249-270`), and list omits it (`:336-341`). Parse/oversize errors alone enter `unreadable`. The list comment explicitly treats a partial directory without `case.json` as non-case (`:336-339`), which conflicts with the requested no-empty-complete rule.
- `CaseListResult` already has the successful `cases` and `unreadable` fields; no additional DTO field is needed. `CaseViewError` currently has only `NotFound` and `Unreadable`, mapped to `not_found` and `record_unreadable` (`:195-218`). Ordinary overview/horizon GETs share `read_case`; `case_view_response` emits those existing classes (`crates/sea-forge-server/src/lib.rs:2398-2403,2899-2914`). Existing Rust tests pin missing GET as `not_found` and a genuinely absent `cases/` directory as empty success (`case_views.rs:518-531`); there are no tests for enumeration, iterator, metadata, or file-read failures.
- The `Request::CaseList` handler directly serializes `list` (`lib.rs:2396-2397`); unlike case GET, it has no typed error mapping. Its serialization fallback has only `error`, no `error_class`. A failed `case.commit` global `case.submitted` publication is separately ignored (`lib.rs:2814-2822`, CW-14); case-list repair cannot establish that cursor.
- Go `sfwp.Authority.ListCases(ctx) ([]ports.CaseRecord, error)` calls `case_list`, decodes `CaseListView{Cases, Unreadable}`, converts cases, but ignores `Unreadable` (`apps/godspeed-casework-go/internal/adapters/sfwp/authority.go:69-88; frame.go:664-667`). It also does not reject missing/null arrays, so a zero-value view becomes an empty slice. Errors from `Client.Do` already propagate. `LiveSource.NewestCaseID` treats an empty returned slice as no cases (`internal/projection/live.go:173-189`); the world handler then emits `EmptyWorld` with HTTP 200 (`internal/server/server.go:209-220`). `Facts` and the intent staleness check also call list and already propagate list errors (`live.go:41-63; intents.go:448-466`). The existing live adapter test confirms successful committed cases appear in the list (`internal/adapters/sfwp/live_verbs_test.go:100-119`).

## Minimal repair alternatives

1. **Preserve successful wire DTO; fail top-level when inventory cannot be enumerated.** Internally return a `Result` from the Rust list operation (or a separate fallible list function used by the sole production handler). Treat `NotFound` for `cases/` as empty only after confirming the configured cell root exists; propagate permission/I/O/non-directory failures. Do not flatten iterator errors: with no trustworthy case ID, fail the whole list. A known entry with failed type/stat or an existing case directory with missing/unreadable `case.json` can remain in the existing `unreadable` ID array. Keep ordinary missing-case GET mapped to `not_found`; if sharing the reader, distinguish OS `NotFound` from other I/O errors and preserve GET’s missing case behavior. Go `ListCases` must reject a nonempty `Unreadable` array as incomplete (using its existing `error` return), so empty bootstrap cannot consume it. This adds no JSON field, verb, ID grammar, or identity rule. The Rust function signature changes; top-level error-class mapping must reuse an existing class and be adjudicated rather than guessed.
2. **Keep `list` signature by moving failure handling to a new fallible wrapper.** This may reduce compatibility impact for internal Rust callers, but the handler must use the wrapper; leaving any production path on the old empty-default helper preserves the unsafe behavior. It still needs the same established failure classification and Go unreadable handling as option 1.
3. **Go-only strictness is insufficient.** Rejecting nonempty `Unreadable` prevents false-empty results for known records, but cannot detect `read_dir` failures, skipped iterator errors, failed directory stats, or IDs silently omitted by Rust. It cannot independently make the existing empty result trustworthy.

For a genuinely fresh cell, preserve empty-success only when the cases directory is absent under an otherwise valid existing cell root. A readable empty directory is also an empty inventory. A partial existing case directory or any unreadable case must not produce a complete-empty claim; retain any readable cases plus known unreadable IDs in the successful DTO, while the Go consumer treats that result as incomplete for world bootstrap. Error text should avoid filesystem paths and payload data.

## Compatibility and review boundary

No option should add a `CaseListResult` field, public error enum/class, dependency, kernel verb, ID grammar, or policy/identity rule without a separate decision. If the top-level error uses existing `record_unreadable`, it broadens a class currently documented as one case record being unreadable; `server_unavailable`/`internal_error` have different existing meanings. Root must choose an accurate existing mapping, or request a separately reviewed public contract change. Changing the public Rust `list` signature or Go `CaseAuthorityPort`/`ListCases` interface needs architecture/API review. A new error envelope/class or changed successful-result semantics needs governing spec and ADR review; operator review is required before any public compatibility expansion. The smallest no-wire-shape path is a Rust-internal fallible listing plus strict handling of the already-present unreadable array in Go, subject to root’s error-class decision.

This only classifies observed failures. `CaseRunner::write_json` uses direct `fs::write`, not temp-file/rename (`crates/sea-forge-case-runner/src/lib.rs:570-575`); listing has no lock with writers. Therefore a successful scan still does not prove atomic snapshot completeness under concurrent mutation. CW-13’s failure distinction does not resolve that race, and CW-14’s discarded publication result remains a separate cursor/readiness issue. No filesystem snapshot, durable cursor, or bootstrap guarantee should be claimed from this correction alone.
