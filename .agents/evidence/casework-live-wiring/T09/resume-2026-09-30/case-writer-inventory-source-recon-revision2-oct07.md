## Scope boundaries and evidence

Approval resolution is explicitly included only in the broad “case-keyed state” sense: its case ledger stream is stored under the case identifier and the shared helper can affect approval observations. It does not alter the directory membership object (`case.json`) or `case-events.jsonl`; a narrower inventory of directory-backed membership/DTO writers may exclude it, but must not silently treat it as a directory case mutation. The CLI and server approval paths are separate, and server publication after approval is best-effort.

The source paths above are the known production writers found in the bounded Rust server, CLI, and case-runner trees. Search results do not establish that every arbitrary external actor, shell script, plugin, or out-of-tree process is absent. Likewise, a mutex or lock observed in one path is stated only for that path and process.

Graft was used first: repository map and focused `find_all`/`trace_calls` queries for case records, CLI dispatch, and `run_stage_case`/`save_case`. Direct source was then read to verify exact dispatch and helper paths. Graft's `trace_calls(save_case, direction=in, in=crates/sea-forge-cli)` did not show the `manager.rs` caller, while direct source at `commands/manager.rs:247-290` calls the imported helper; direct call-site verification therefore supersedes graph absence for this edge.

The production Rust deletion/rename matches included migration file relocation and removal of empty legacy run directories, plus case operation temporary-file replacement; unrelated socket, correlation, and secret cleanup also matched the broad file-operation pattern. No production case-directory tree deletion or restore path was found in these bounded trees. This is not a claim about manual filesystem activity or code outside the listed roots. Go results are bounded to the named Go subtree and patterns. Tests and readers also match file literals but are not writer entrypoints.
