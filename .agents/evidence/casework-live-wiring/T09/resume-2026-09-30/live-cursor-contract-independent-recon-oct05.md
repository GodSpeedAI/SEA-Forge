# Live cursor contract: independent source recon (2026-10-05)

## Scope and result

This is a read-only source and history reconciliation for the cursor carried through the existing SEA Forge event feed, Go world/SSE/intent/trajectory paths, and the approved T09 `execution_observation` contract. No source, test, schema, status, or Git state was changed. This report records a contract/source mismatch; it does not select a repair or approve an interface change.

## Contract evidence

The existing canonical UI contract does not describe the cursor as opaque. The T01 confirmation records the snapshot/patch stream as keyed by the `"<epoch>.<seq>"` cursor which doubles as `Last-Event-ID` (`.agents/evidence/casework-live-wiring/T01/confirmation.md:54-59`). The canonical Cognitive World schema requires `^[0-9]+\\.[0-9]{10}$` and calls it a monotonic logical sequence cursor (`.agents/reports/interface-contracts/schemas/cognitive-world.schema.json:29-33`). The Interaction Intent schema gives `client_cursor` the same pattern and says it is the cursor of the snapshot the user acted on (`.agents/reports/interface-contracts/schemas/interaction-intents.schema.json:53-56`). TypeScript repeats the epoch/sequence example on `CognitiveWorldSnapshot.cursor` (`.agents/reports/interface-contracts/typescript/types.ts:101-105`).

The shared event envelope also requires the same numeric-dot pattern (`.agents/reports/interface-contracts/schemas/event-stream.schema.json:24-27`). The operator-approved T09 amendment adds `execution_observation` as an informational side channel whose cursor is the latest real case cursor and must not become an SSE ID; it retains the existing event cursor regex (`event-stream.schema.json:174-183`). The T09 proposal explicitly says to copy the latest real case cursor, never create a logical trace cursor, and omit the SSE `id:` for this event (`.agents/reports/casework-live-wiring/t09-contract-extension-proposal.md:31-35`). The project spec records those same semantic rules (`.agents/specs/godspeed.casework-cognitive-environment-spec.yaml:82-88`).

History identifies the current normative mismatch's introduction points. The T01 contract commit is `59b8ff4` (2026-09-23); the T09 contract confirmation is `b608771` (2026-10-01). `git show b608771 -- .agents/reports/interface-contracts/schemas/event-stream.schema.json` shows the T09 change adding the observation event and its event-specific cursor declaration while retaining the existing shared numeric-dot cursor rule. The canonical Cognitive World and Interaction Intent cursor rules predate that T09 change; their schema/type definitions are tracked at `19730c1` / `59b8ff4`. The T09 proposal marks the amendment operator-approved and runtime-pending (`t09-contract-extension-proposal.md:5-7`); the checked-in spec's change rule requires an ADR/spec update before implementation (`godspeed.casework-cognitive-environment-spec.yaml:25`).

## Actual kernel-to-gateway cursor path

The Rust server's `EventFrame.cursor` is documented as the event ledger entry's `entry_ulid` (`crates/sea-forge-server/src/sfwp/events.rs:16-21`). `append_event` assigns `entry.entry_ulid.clone()` directly (`:59-88`); replay reconstruction does the same (`:91-100`). The ledger's ULID generator constructs 26 characters from the Crockford alphabet `0123456789ABCDEFGHJKMNPQRSTVWXYZ` (`crates/sea-forge-ledger/src/types.rs:81-93,127-147`). Thus the emitted form is an opaque 26-character ULID, not the schema's decimal-epoch, dot, ten-decimal-digit form.

The Go SFWP `Event` holds cursor as a string and `DecodeEvent` returns the decoded event without cursor conversion (`apps/godspeed-casework-go/internal/adapters/sfwp/frame.go:891-900,909-919`). Its subscription resumes using the last delivered cursor as `from` (`internal/adapters/sfwp/subscribe.go:85-102`). The feed copies `ev.Cursor` to `KernelEvent.Cursor` (`internal/server/feed.go:21-40`); the relay retains that raw value per case (`internal/server/relay.go:99-109`) and returns it from `CursorForCase` (`:170-175`). No inspected hop normalizes the cursor.

For a live world, `handleWorld` passes that per-case raw relay cursor to `WorldSource.Snapshot` (`internal/server/server.go:209-230`); `LiveSource` places it in `CaseFacts.Cursor` (`internal/projection/live.go:124-133`), and `projection.Build` copies it to the canonical snapshot (`internal/projection/builder.go:44-47,100-103`). The current SSE path sends each retained revision's raw cursor both as the SSE ID and JSON envelope cursor (`internal/server/server.go:288-292,367-373`). Revision storage compares/indexes cursor strings as-is and uses them for replay and lookup (`internal/projection/store.go:111-119,149-153`).

For intents, the handler compares submitted `client_cursor` directly to `CursorForCase` and returns the observed cursor in stale refusals (`internal/intents/intents.go:50-60,154-163,434-446`). Consequently snapshots, ordinary live SSE events, and freshness checks share the same raw ULID cursor value; no Go-side epoch/sequence mapping was found in these paths.

For trajectory, the endpoint copies retained revision cursors into `base_cursor`, `head_cursor`, and each checkpoint (`internal/server/trajectory.go:12-19,72-90`). The checked-in TypeScript declares these as strings (`types.ts:406-423`), but the inspected interface-contract `schemas/` directory has no dedicated trajectory schema. The event-stream and Cognitive World schema patterns therefore establish explicit constraints for event/snapshot/intent cursors; applying those regexes to trajectory JSON is not independently established by a trajectory schema in this checkout.

## Findings and limits

1. The actual SFWP event cursor is a 26-character Crockford ULID and is propagated verbatim through the Go world, SSE, intent-freshness, and trajectory paths. The canonical event, snapshot, and client-intent schemas require `^[0-9]+\\.[0-9]{10}$`. Those two syntactic forms are disjoint, so actual production cursor values do not satisfy those schemas as written.
2. The approved T09 rule intentionally reuses the latest real case cursor for an informational observation. Its no-`id:` rule prevents the observation from changing resume position, but it does not reconcile the JSON cursor's pattern with the real cursor emitted by the kernel.
3. Current `handleEvents` emits retained snapshot revisions, not `execution_observation` events (`server.go:288-292,348-373`). T09 says runtime is pending; this report does not claim the new event is currently emitted.
4. The T01 confirmation establishes that the authored canonical UI contract intended epoch/sequence syntax; the T09 amendment affirms “latest real case cursor” without changing that syntax. The proposal and history do not specify a conversion rule or amend the normative cursor grammar.
5. This recon did not validate all client-side cursor comparators or every historical fixture. It establishes the actual producer-to-Go-consumer path above and the canonical schema/type/spec statements cited. No schema or identifier decision is made here.
