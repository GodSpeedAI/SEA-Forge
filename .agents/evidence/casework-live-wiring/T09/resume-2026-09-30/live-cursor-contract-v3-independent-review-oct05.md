# Independent review: live cursor contract V3

Date: 2026-10-05  
Disposition: **REJECT for operator approval; retain HOLD.**  
Scope: source/spec review only. No implementation or validation gates were run.

## Review basis

Reviewed the original proposal and rejection, V2 and its independent rejection, V3, the frozen casework spec/schema contract, and current Go/Rust/UI source. The reviewed V3 SHA-256 is `04f2675d6bc4ece8bec3967c3e82e95240ac7325c0964cf0c31b9b6837793d6c`; V2 is `f38d2428f0bc21d46b94fe2303996bbb8cee5ccb9247029b323ae489f9b36788`.

## What V3 corrects

V3 materially repairs the V2 cold-start defect: V2 replayed old durable events through the current `LiveSource`, so present-day Facts could be mislabeled as past revisions. V3 instead prohibits fabricated backlog captures and proposes one current baseline capture per existing case at a real latest cursor (V3 lines 11–37). That is consistent with the frozen immutable-capture model: it honestly disclaims as-of-event reconstruction and separates capture time from event time.

V3 also resolves V2's ambiguous feed acknowledgement: a channel delivery is not an ACK; successful append/head publication or explicit fail-closed gap disposition is required (lines 39–57). It adds pre-header 503 readiness when no real retained boundary exists (lines 66–76), and an empty-world bootstrap without synthetic IDs/cursors or empty ordinary revisions (lines 78–97). These are substantive improvements over V2 and are directionally consistent with immutable history and real-cursor requirements.

## Approval blockers

1. **The ordinary ID compatibility claim is contradicted by actual producers.** V3 lines 101–107 says to preserve deterministic `world_id` construction and admit the cursor union in its suffix. The current producer at `apps/godspeed-casework-go/internal/projection/builder.go:99-104` emits `world-` plus case ID, with no cursor suffix; the frozen schema instead requires `^ws-[a-z0-9_.-]+-[0-9]+\\.[0-9]{10}$` (`.agents/reports/interface-contracts/schemas/cognitive-world.schema.json:19-32`). V3's cursor-union inventory therefore does not describe the producer it claims to preserve.

   There is a second, independent mismatch: the same frozen schema requires case IDs matching `^case-[a-z0-9_.-]+$` (schema lines 24–27). The actual kernel generator emits `case_<UTC timestamp with uppercase T/Z>_<hex>` (`crates/sea-forge-core/src/ids.rs:32-47`), and `case.commit` uses it directly (`crates/sea-forge-server/src/case_dispatch.rs:77-89`). The case-view validator permits underscore and uppercase (`case_views.rs:237-247`). A cursor-union change does not make ordinary snapshots schema-valid. V3 must inventory and resolve both producer formats without silently converting existing IDs.

2. **Bootstrap is not a reviewable wire contract or usable empty-state flow yet.** V3 itself says the exact bootstrap DTO and entry compatibility still require source review before approval (lines 95–97). Its proposed payload lacks property names, discriminant, types, template representation, and failure shape. Current `WorldHistory` initialization expects a revision (`apps/godspeed-cognitive-ui/src/model/store.ts:12-18,44-49`); current empty-world `centerActions` returns no actions when there is no focused object (`src/app/App.tsx:238-253`). Thus “render the available entry flow” does not identify a current UI path or concrete state transition.

   An existing case-entry path is available: `proposals.ts:68-91` obtains a preflight digest, dispatches `PROPOSE_CASE`, then focuses the returned case. Do not invent a kernel verb or drop preflight. But it sends empty `case_id` and `client_cursor`; the frozen intent schema requires both and constrains them to nonempty case/cursor patterns, while its action enum omits `PROPOSE_CASE` (`interaction-intents.schema.json:7-14,26-44,49-56`). The V3 proposal must explicitly account for that approved create-case exception and for waiting until the newly committed case has a real ready cursor before ordinary history/SSE begins. The existing `/api/events` handler has no selected-case input (`internal/server/server.go:293-317`), so “case-scoped stream” and per-selected-case readiness also need a concrete route/interface plan.

3. **Cold-start frontier discovery and race closure are underspecified.** V3 lines 20–35 proposes `case.list` plus paged `events.get_range` to find a “reconciled ledger frontier,” but no current range result supplies a head/frontier token; the response contains event frames only (`crates/sea-forge-server/src/lib.rs:2349-2361`). `events.get_range` defaults to a capped range and reads the ledger entries (`sfwp/events.rs:165-207`); `LedgerStream::read_entries` materializes every entry into a vector (`sea-forge-ledger/src/types.rs:784-801`). Therefore the 500-frame page cap bounds returned frames, not kernel memory or repeated scan cost. The proposal must define how the frontier is established, how a case created around inventory/scan completion is reconciled, and what bounds startup time/work. Otherwise a newly committed case can fall between the case inventory and feed watermark.

4. **Gap atomicity and readiness cannot yet be implemented from current interfaces as stated.** V3 correctly requires invalidation/cancellation atomic with replay/subscriber registration and asks for a concrete Store/coordinator decomposition before implementation (lines 59–64), but that decomposition is still absent. Current Store is global, unfiltered by case, and retains global cursor ordering (`internal/projection/store.go:55-65,149-160,193-213`). Current SSE registers that global subscription and writes HTTP 200/hello before any case-boundary check (`internal/server/server.go:293-324`). A case-specific 503 before headers, scoped replay, gap invalidation, and cancellation need a route identity and lock/dequeue/write ordering absent from these interfaces. The proposal recognizes this as a hold, so it is not ready for operator approval.

## Required next proposal revision

Keep V3's useful semantic corrections: opaque exact cursor union, ordinal ordering, immutable capture-time history, no cold fake backlog, explicit gap disposition, no synthetic resync boundary, and cursorless bootstrap outside ordinary history. Before operator approval, provide the exact bootstrap/API/UI variant and create-case transition; reconcile both canonical ID grammars with actual producers; define a race-safe latest-cursor/frontier discovery procedure and its real memory/work bounds; and give the concrete per-case Store/stream invalidation and readiness boundary. Preserve existing kernel verbs and preflight authority. Update schema/docs together only after the needed contract review; do not authorize public edits through this source review.

## Material deltas from V2 and frozen policy

V3 changes cold history from replaying all old events into current Facts to one current capture per extant case at its latest real cursor; changes acknowledgement from channel delivery/implicit progress to successful publication or explicit gap; adds per-case gap invalidation and cancellation; specifies 503 before SSE headers and real-boundary resync; adds a distinct empty-cell bootstrap and UI state; and adds `world_id` to the contract inventory. Those changes generally correct defects identified by the V2 rejection and do not themselves violate the frozen prohibition on synthetic identities. The new `world_id` preservation statement is factually incorrect, and V3 leaves the bootstrap, entry exception, frontier, and gap interface unresolved. No approval is recommended until those are resolved in a new proposal.
