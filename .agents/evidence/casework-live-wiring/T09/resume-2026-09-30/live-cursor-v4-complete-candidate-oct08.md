# Live cursor V4 complete candidate — 2026-10-08

**Status: candidate for root architecture review only.** This document is not an approved contract, operator approval, source release, or runtime proof. It proposes additive changes to existing interfaces and identifies changes that require exact operator approval before implementation. No new kernel verb is proposed.

## 1. Binding constraints and current facts

Keep the approved revision-3 bootstrap boundary: `{snapshot: ...}` or a mutually exclusive `{bootstrap:{status:"no_cases",timestamp,perspective,templates}}`; bootstrap contains no case/world ID, cursor, revision, or history. Its timestamp is capture time, templates are the existing canonical entry options, and it is an honest as-of response—not an atomic no-case interval. Preserve preflight, the existing `PROPOSE_CASE` flow, returned actual case ID, and require that exact case to become ready before mounting ordinary history or SSE. Explicit case selection never redirects. Only an absent case query may select the default case/bootstrap. A nonempty `cursor` selects retained history; absent or empty `cursor` uses the live path, matching the factual erratum (`server.go:188-230`).

The frozen source contracts and implementation disagree. Kernel cases are generated as `case_YYYYMMDDTHHMMSSZ_<6 lowercase hex>` by `ids::case_id` (`crates/sea-forge-core/src/ids.rs:6-10,32-47`), while the authored world schema requires `^case-[a-z0-9_.-]+$` (`.agents/reports/interface-contracts/schemas/cognitive-world.schema.json:24-27`). Go and the local UI produce `world-` plus the exact case ID (`apps/godspeed-casework-go/internal/projection/builder.go:99-104`; `apps/godspeed-cognitive-ui/src/adapters/local/localAdapter.ts:414-416`), while the frozen schema requires a `ws-...-<numeric cursor>` world ID (`cognitive-world.schema.json:19-22`). Go copies the supplied cursor (`builder.go:100-104`); the actual SFWP event cursor is the events-ledger `entry_ulid` (`crates/sea-forge-server/src/sfwp/events.rs:19-24,61-89`), not the schema’s numeric-dot value. Do not normalize or re-key IDs.

The interaction schema also does not describe the existing creation path: `PROPOSE_CASE` is omitted and `case_id`/`client_cursor` are required to match nonempty patterns (`interaction-intents.schema.json:7-56`), while the UI sends empty values for this one create-only operation after preflight (`apps/godspeed-cognitive-ui/src/app/proposals.ts:60-80`) and Go has a narrow `PROPOSE_CASE` stale-guard exception (`apps/godspeed-casework-go/internal/intents/intents.go:154-196`). The proposal changes no authority decision. Preserve D-2’s verified gateway principal, allowlisted delegation, dual-principal audit, and end-user SoD rule (`.agents/reports/casework-live-wiring/decision-log.yaml:D-2`). C-2 remains held: direct broadcast is not durable ordering, opaque ledger IDs must be ordered by append ordinal, cold current-Facts replay cannot invent old captures, and bootstrap is not a case revision (`decision-log.yaml:C-2`).

## 2. Opaque cursor and identity amendments

Keep `cursor` as the exact nonempty `entry_ulid` of the real events-ledger entry. It is opaque at every Go/UI boundary: no parsing, normalization, lexical comparison, numeric conversion, or regeneration. Use its durable `append_ordinal` for ordering and stale comparisons. Add `append_ordinal: uint64` to the existing SFWP `EventFrame`, Go `KernelEvent`/`Revision`, and ordinary `CognitiveWorldSnapshot` as `cursor_ordinal`. A frame is ordered only by that number; duplicate delivery is the exact `(append_ordinal,cursor)` pair, and an ordinal/cursor mismatch is a protocol-integrity error. `LedgerEntry.append_ordinal` already supplies the durable producer under `LedgerStream::with_exclusive_lock` (`crates/sea-forge-ledger/src/types.rs:191-207,701-721,1000-1069`); `events::frame_from_entry` and `append_event` are the existing projection points (`crates/sea-forge-server/src/sfwp/events.rs:61-105`).

Amend the authored schema, Go contract and canonical TypeScript together:

* `cursor` becomes a nonempty opaque string with no lexical/numeric pattern. `cursor_ordinal` is a nonnegative safe integer and is the only ordering value. The UI continues to key history by exact cursor but compares/sorts by ordinal.
* `case_id` accepts the actual generated grammar `^case_[0-9]{8}T[0-9]{6}Z_[0-9a-f]{6}$` and the currently frozen legacy form `^case-[a-z0-9_.-]+$` as a union. Existing values are preserved byte-for-byte; the union does not translate IDs.
* `world_id` remains the actual stable `world-<case_id>` value. Its schema accepts precisely those two corresponding forms. It is a stable case-world identity, not a per-capture ID; exact capture identity is the `(cursor,cursor_ordinal)` pair. Revise the schema description that currently calls it a unique snapshot identifier.
* `InteractionIntent.client_cursor` remains the exact cursor string. The gateway resolves it through its retained exact cursor index and compares ordinals; unknown/evicted cursor is rejected as stale/unavailable, never compared lexically. No client-supplied ordinal is trusted.

This corrects frozen grammar/meaning and adds a public ordinal field; it is a public schema/API change requiring exact operator approval and authored schema/ADR updates before code. The legacy branch is for already persisted/fixture IDs, not a normalization rule. Whether every legacy value is admitted by the production parser remains an explicit root decision.

## 3. Existing-verb frontier and append index

Do not add a kernel verb. Extend the existing `events.get_range` request/response, whose current request is cursor-bounded and whose response is only `{"events": [...]}` (`crates/sea-forge-server/src/lib.rs:2349-2361`; `sfwp/events.rs:169-208`). Proposed typed page:

```text
EventsRangePageRequest {
  after_ordinal?: u64,
  through_ordinal?: u64,       // pinned on the first response, fixed for later pages
  continuation?: RangeContinuation,
  limit?: u32                  // default 500, hard maximum 500
}
EventsRangePage {
  events: EventFrame[],        // each has exact cursor and append_ordinal
  head: { cursor: string, append_ordinal: u64 },
  scanned_through_ordinal: u64,
  next: RangeContinuation | null,
  complete_through_head: bool
}
```

The first request snapshots the durable ledger tail under the ledger’s existing file-lock discipline and returns it as `head`; later pages must present that exact pinned head. `RangeContinuation` binds the exact last scanned cursor, ordinal, byte offset, and pinned head. The reader validates the preceding complete ledger row at that offset and rejects a forged, stale, cross-ledger, or mismatched token; continuation is a page locator, not an event cursor or authority credential. Pages are append-ordinal ordered, inclusive of neither `after_ordinal` nor beyond `through_ordinal`. The exact event cursor remains in each frame and SSE ID. The existing `from_cursor`/`to_cursor` request remains supported for compatibility but cannot be used for repeated full-history paging because resolving every page by scanning the prefix is unbounded work.

The current `get_range` calls `ledger.read_entries()` before filtering/capping; the 500-frame limit therefore caps the result, not memory or scan (`events.rs:169-208`; `LedgerStream::read_entries` at `crates/sea-forge-ledger/src/types.rs:784-801`). Replace this path with a seekable line reader using a fixed-size buffer and the continuation offset. Each request may inspect at most 500 ledger rows and emit at most 500 event frames/1 MiB serialized response; reject a single oversized row with typed `EVENT_RECORD_TOO_LARGE`, never truncate it. Try the existing stream lock for at most 50 ms; contention returns typed `EVENTS_BUSY` without a partial page. The pinned tail is read/validated with a bounded final-row buffer under the same lock. A partial/corrupt tail is an integrity error; no page claims completion over it.

Cold start must not scan an unbounded ledger synchronously or treat a page cap as a bound on total work. Add a derived `case-head-index-v1` checkpoint (new durable derived state, not event history) containing the exact events-ledger head pair, a map from exact `case_id` to each case’s latest `{cursor,append_ordinal}`, and a version/checksum. It is rebuildable only from the authoritative events ledger. Update it in append-ordinal order after each successful event append and before `event_bus.send`; serialize the existing `ServerState::publish_event` path (`crates/sea-forge-server/src/lib.rs:208-234`). The in-tree global event append producers all route through this method: `case.submitted` and config error (`lib.rs:2764-2832`), case trace/mutation events (`crates/sea-forge-server/src/sfwp/case_mutations.rs:147-193`), approval decision (`lib.rs:3034-3134`), delegation start/cancel (`lib.rs:3139-3339`). Case-local `CaseRunner::append_event` calls are separate case-ledger writes and are not global event producers (`crates/sea-forge-case-runner/src/lib.rs:31-72`). Any future/global writer bypassing `publish_event` must be detected by comparing the index head with the durable ledger head before readiness; until indexed through the real head, projections remain unavailable.

The append is authoritative first. If the process dies after ledger append and before index replacement, the old index is behind and startup repairs from its last exact ordinal using `events.get_range` pages. If the index is ahead, checksum-invalid, or its cursor/ordinal pair disagrees with the ledger, mark `rebuilding` and rebuild from the ledger; never accept the index as truth. Persist repair progress only as derived index state, and atomically publish `ready` only after the index reaches the pinned durable head. A crash during replacement leaves either the old or new complete checkpoint. The event bus is only a wake hint; periodic range reads from the acknowledged ordinal catch missed or reordered broadcasts, including a crash before broadcast.

Proposed bounds: index at most 4,096 cases/8 MiB; page at most 500 rows/1 MiB/50 ms lock wait; reconciliation worker at most two pages and 500 ms per scheduling turn; one rebuild attempt at most 1,000,000 ledger rows or 10 minutes. On a rebuild limit, preserve exact continuation and a typed `rebuilding_limit` unavailable state; resume only through a later bounded maintenance attempt. A ledger exceeding the configured lifetime migration ceiling remains unavailable until an operator-approved migration/cap decision. These are proposed limits, not existing guarantees. They bound memory and each unit/attempt of work while making the legacy-history availability tradeoff explicit.

## 4. Complete inventory and concurrent changes

Change the existing Rust `case.list` implementation from infallible omission to fail-closed success/error semantics. A success is a complete `CaseListResult` with required non-null `cases` and `unreadable: []`; `cases: []` means complete empty only when the cases root was readable and complete. A genuinely absent `cases/` below a readable cell root is complete empty. Permission/I/O/iterator/non-UTF8/metadata failures, unreadable case records, a case directory with a missing/partial `case.json`, a malformed record, case-count cap, or response-byte cap returns typed error; no partial list is serialized as complete. Today `case_views::list` returns a default on `read_dir` error, flattens iterator failures, skips non-UTF8 names, and omits `NotFound` (`crates/sea-forge-server/src/sfwp/case_views.rs:310-356`); `Request::CaseList` serializes it directly (`crates/sea-forge-server/src/lib.rs:2396-2397`). The Go `Authority.ListCases` must require the `cases` array and reject nonempty `unreadable`, rather than ignoring it (`apps/godspeed-casework-go/internal/adapters/sfwp/authority.go:69-88`). Preserve the current DTO on complete success; use existing SFWP error envelope for failure. Cap a response at 4 MiB/4,096 cases; exceeding either is unavailable, never truncated success.

The startup coordinator uses only the strict inventory and complete head index. It samples the durable index/head pair before and after the list. If they differ, it retries at most three times; continued mutation returns typed `INVENTORY_CHANGING` unavailable. This is race detection, **not an atomic inventory proof**. A listed case must have an exact indexed real event cursor no later than the sampled head; otherwise quarantine that case as unavailable pending ledger reconciliation. A case created after the inventory capture is discovered by the next ordinal page. A complete-empty response is honest at its inventory capture time; a case may commit immediately after it. Do not promise a no-case interval or claim that the filesystem list and event head are one atomic snapshot. Mutations observed during `Facts` capture may mean current Facts are later than the triggering event; retain actual capture time and do not claim as-of-event reconstruction.

At process start, verify/rebuild the derived index first. Then obtain strict inventory and stable head. Do not fabricate old revisions by replaying old events through current Facts. For each existing case, baseline on demand or once per selected case from `WorldSource.Facts/Snapshot`, using the exact latest real indexed case cursor and actual `now` capture timestamp. Record `capture_kind: "process_baseline"` versus `"event_capture"` in the revised snapshot contract. The baseline is one new immutable current capture, never a historical reconstruction. Cases with no verified cursor, incomplete inventory, or unready index return unavailable. A valid empty inventory alone permits the revision-3 bootstrap arm.

On live operation, the relay consumes durable pages strictly by `append_ordinal`. It deduplicates exact cursor/ordinal pairs; never compares event IDs lexically. It acknowledges a page only after every case frame has either (a) produced and appended a valid immutable capture, (b) atomically invalidated that case’s projection with a gap marker, or (c) received an explicit no-case projection disposition. A frame delivered to broadcast is not acknowledged. A range/list/facts/index error does not advance the global acknowledged ordinal. It sets projection readiness unavailable and retries from the last acknowledged ordinal. Events with no case ID have a typed no-projection disposition and still advance the page acknowledgement after that disposition is recorded.

For a failed case projection, mark that case unavailable and invalidate its replay window before acknowledging the frame; unaffected case histories continue. Later successful capture at a real cursor creates a fresh ready boundary. Old resume cursors yield `resync_required` pointing to the real oldest retained cursor/ordinal; no empty or synthetic boundary. A successful case commit whose `case.submitted` publication/index update fails remains committed; return the actual case ID with a typed projection-pending outcome or equivalent existing correlated result, never an ambiguous fresh-create retry. It becomes ordinary-ready only when the durable range/index reconciliation observes a real case event and a capture is accepted.

## 5. Per-case Store, retention, and SSE boundary

Replace global lexical `projection.Store` history with a case-keyed store ordered by numeric append ordinal. Current `Store.Append` compares `rev.Cursor` strings, broadcasts one global subscriber set, retains 512 full snapshots by count only, and allocates replay buffers proportional to replay (`apps/godspeed-casework-go/internal/projection/store.go:23-39,149-227`). The route has no `case_id`, registers global subscription, writes `200`/hello before its cursor-retention check, and compares cursors lexically (`apps/godspeed-casework-go/internal/server/server.go:293-376`). The candidate keeps the same `/api/events` route but requires exactly one valid `case_id` for ordinary revision streams; the informational execution-observation side channel remains under its approved contract and carries no SSE ID.

`Store.AppendCase(revision)` accepts only nonempty exact cursor plus ordinal and rejects any non-increasing ordinal, mismatched duplicate pair, case ID mismatch, or stale generation. Retain immutable `Revision{CaseID,Cursor,AppendOrdinal,CapturedAt,CaptureKind,Snapshot,Facts}`. `Store.InvalidateCase(caseID, reason)` and subscriber registration use the same mutex: it marks the case unavailable, clears all old replay data, closes/removes that case’s subscriber channels, and increments an in-memory generation. A later accepted capture starts a fresh retained boundary. The coordinator is sequential; its captured generation is checked at append so a delayed old capture cannot republish after invalidation.

Concrete proposed memory/connection bounds (new availability policy requiring approval): each serialized snapshot ≤1 MiB; at most 64 revisions/4 MiB per case; at most 64 MiB retained across the process; at most 128 case heads; at most 32 active SSE connections/process; each live queue ≤2 frames/2 MiB. Evict oldest historical revisions first and maintain exact cursor/ordinal indexes. If a client's cursor was evicted/unknown, return resync with the actual oldest retained pair. Preserve the newest capture for a ready case only while within the total byte cap; if it cannot fit, invalidate that case and return unavailable—never truncate snapshots or evict silently. A slow connection is closed when its bounded queue fills; reconnect replay follows the same exact cursor/ordinal checks. Counts alone do not claim a byte bound.

Actual request ordering for `GET /api/events?case_id=...&last=<opaque-cursor>`:

1. Validate exactly one nonempty case selector and no duplicate selector; authenticate session and verify perspective before any subscription or stream headers (`server.go:293-313`). Validate SSE support. A missing/invalid case returns typed 400.
2. Call `Store.PrepareCaseSubscription(caseID,lastCursor)` under the Store mutex. It checks case readiness/gap status, resolves exact cursor membership, determines retained replay using ordinals, copies at most the bounded replay into the fixed-capacity queue, and registers the subscriber before releasing the lock. No callback, source read, blocking write, or cancellation runs under the Store mutex.
3. If unavailable, incomplete, or cursor requires resync, return typed 503/409 JSON before `WriteHeader`; for resync include only actual oldest/current real cursor+ordinal. The client fetches the exact current case snapshot, clears case history/cache, and retries using its cursor. If ready, set SSE headers, write 200 and hello carrying selected case/current pair, then flush.
4. Dequeue outside locks and serialize each immutable case revision as `id: <exact opaque cursor>` plus an envelope with `cursor_ordinal`. Apply no string ordering. On disconnect/queue overflow/gap, unregister outside blocked network writes. A closed channel never implies successful replay; the next request re-enters the same locked boundary.

The atomicity guarantee is only between Store readiness/gap mutation and replay selection/registration. It does not make kernel Facts and filesystem state atomic. The global store is not rewritten into a second event authority: SFWP events ledger remains truth; Store is bounded derived capture history.

## 6. HTTP errors, bootstrap, and UI readiness

Use distinct typed outcomes: complete-empty inventory → revision-3 bootstrap `200`; incomplete/error/cap/frontier repair in progress → `503 unavailable` with stable `inventory_unavailable`, `frontier_rebuilding`, or `projection_gap` code; explicit missing/unknown case → `404` (not redirect); explicit existing case without a real retained/indexed cursor → `503 case_not_ready`; stale/evicted history cursor → `404` for world history or pre-header `409 resync_required` for SSE. A transport, schema, or inventory error can never be interpreted as an empty case list. Rust `case.list` must distinguish missing cases directory under valid root from permission/IO failure. Go maps existing typed SFWP error class to these typed HTTP errors; this mapping and public code vocabulary require approval.

At session startup the UI validates `WorldResponse` before using it. Snapshot arm requires matching explicit case ID and nonempty exact cursor plus safe integer ordinal; bootstrap arm stays outside `WorldHistory`, cursor cache, and `App`. The authored `world-response.schema.json` and hand-written parser enforce exactly one arm and reuse canonical `ActorPerspective`/`TemplateEntryOption` types per revision 3. Missing/error/inventory-incomplete stays unavailable/retry, never bootstrap. Refresh is authenticated, one at a time, at least one second apart, aborted on session/view disposal or successful transition. The existing `SessionApp` loads history before mounting `App` (`apps/godspeed-cognitive-ui/src/main.tsx:65-110`), so the approved bootstrap branch must happen before that load; only a validated ordinary snapshot can create history, focus, or attach case SSE.

Keep the current create-case preflight sequence and narrow empty identifiers. After a matching accepted `PROPOSE_CASE` response, retain the returned real case ID and do not create a new intent. Poll/refresh only that explicit case under a bounded wait. Open history/SSE only after a validated ordinary snapshot with real cursor pair; timeout/error remains accepted-but-not-ready and does not become a second create. Revise `InteractionIntent` schema only with an action-specific `PROPOSE_CASE` conditional requiring empty case/cursor exclusively for that action and preserving current nonempty cursor/case rules for all others. Keep D-2 identity, CSRF, rate limits, server-derived actor, preflight digest, and idempotency unchanged. The approved bootstrap revision-3 proposal contains further UI controller/privacy boundaries; they remain binding and separately held.

## 8. Required exact approvals and unresolved root decisions

This candidate changes the public snapshot/intent/event schemas and SFWP `events.get_range` response; changes cursor meaning from numeric-dot to exact opaque event IDs; introduces a durable derived cursor index and recovery lifecycle; tightens `case.list` error semantics; changes world ID’s documented identity; adds `cursor_ordinal`/`capture_kind`; creates case-scoped SSE/readiness semantics and public HTTP error codes; and imposes availability/resource caps. Each requires an authored spec/schema/ADR update and exact operator approval before source or public changes. No dependency, new SFWP/kernel verb, second authoritative event history, synthetic ID/cursor, or preflight removal is proposed.

Root must decide before any implementation: (1) approve/reject the derived per-case head index and its 1,000,000-row/10-minute repair ceiling; (2) approve/revise exact resource caps and the unavailable behavior when exceeded; (3) approve the case/world legacy+actual grammar union and stable `world_id` meaning; (4) approve `cursor_ordinal` and `capture_kind` wire fields; (5) approve exact typed SFWP/HTTP error names and response codes; (6) decide whether any case mutation path can write durable case state without a corresponding global event and, if so, require a kernel event or keep that case unready; (7) decide whether the revision-3 no-case as-of boundary is sufficient despite a concurrent case commit immediately after it; and (8) review whether reusing `events.get_range` with page/head fields preserves SFWP compatibility/versioning.

Known limits remain: the index is derived, never authoritative; cursor/head proof orders durable event rows but does not make case files, `Facts`, and event append one atomic snapshot; a baseline is capture-time truth, not historical reconstruction; cases lacking a real global event cursor remain unavailable; no public V4 or source readiness is approved. Independent critic review and exact operator approval are prerequisites to any implementation.
