## 2. Durable append frontier and bounded index

Extend existing SFWP `events.get_range`; add no kernel verb. Optional `range_version=2` selects the paged contract below. Omission keeps the current response shape but must use bounded reading; unknown versions fail typed. A page carries ordered `EventFrame`s, exact `head:{cursor,cursor_ordinal}`, `scanned_through_ordinal`, a validated continuation, and `complete_through_head`. `cursor_ordinal` is a canonical decimal string representing checked `u64`; clients parse with checked `BigInt`. Exact cursor remains opaque; no ULID parsing or lexical ordering. Bind continuation to stream, pinned head, last complete row/cursor, byte offset, and a checksum; verify the preceding row before seeking. Unknown, cross-stream, stale, forged, or mismatched tokens fail without a partial-complete result.

Current `get_range` materializes `read_entries()` before applying the 500-frame cap (`crates/sea-forge-server/src/sfwp/events.rs:169-208`; `crates/sea-forge-ledger/src/types.rs:784-801`). Replace it with bounded line/offset reading under the existing ledger lock. Per request: at most 500 scanned rows, 500 emitted frames, 1 MiB serialized response, and 50 ms lock wait; oversized rows and lock timeout return typed errors. Reconciliation gets at most two pages or 500 ms per scheduling turn. Preserve exact cursor+ordinal pairs; a cursor/ordinal mismatch, torn row, or bad tail is an integrity failure.

Add derived `case-head-index-v1`, never authoritative event history: exact global head plus latest `{cursor,cursor_ordinal}` per exact case ID, version, checksum, and bounded repair continuation. Cap it at 4,096 cases/8 MiB. Append remains authoritative: after each durable global event append, atomically replace/fsync the index before broadcast. On crash between append and index update, startup pages from the last exact indexed ordinal; missing, ahead, corrupt, or mismatched index stays unavailable until reconciled to a pinned actual ledger head. One rebuild lineage is capped at 1,000,000 rows or 10 minutes active work. Hitting either ceiling preserves continuation and `frontier_rebuilding`; it does not reset automatically. The ceiling is cumulative for that detected lineage. A larger ceiling needs a new operational decision. Broadcast is only a wake hint; periodic range paging repairs dropped/reordered frames and restart gaps.

## 3. Shared case mutation journal and inventory

Introduce a versioned derived journal at `.sea-forge/case-projection-journal/v1/` and one cell-scoped OS file lock used by every supported facts mutation and by Rust-side coherent capture. Use pinned Rust 1.92 `File::lock`; the existing ledger append has its separate lock (`sea-forge-ledger/src/types.rs:701-723`). Lock order is always projection-writer lock, then ledger lock. Never acquire them in reverse. The journal is not authorization and does not replace domain checks. Authenticate/authorize and run existing guards before journal effects. No auth callback, network I/O, or capability execution runs while holding the projection lock; writers hold it only around each bounded durable state-write transaction. Existing long capability work remains outside it, with each resulting persisted transition separately journaled.

Each transaction allocates an operation ULID using the existing ledger ID generator (`sea-forge-ledger/src/types.rs:93-148`), records `operation_id`, exact affected IDs, a fixed mutation-class enum, authority classification from the already-verified caller, prior global head ordinal, schema version, and `pending` state. No credentials, arbitrary request payloads, or raw error strings are retained. Limit one record to 32 KiB, pending journal to 256 records/8 MiB, and lock wait to 50 ms. If capacity or lock is unavailable, refuse before case-visible writes and return a typed unavailable result. Write pending through temp-file write, file sync, atomic rename, and parent-directory sync before mutation. After the durable case writes, append the corresponding real global case event carrying that operation ID; for a path without an existing semantic event use the proposed `case.projection_changed` kind. Then advance the index and durably mark the record complete. Only completed records are prunable; never evict pending records to make room. A full pending journal remains unavailable until bounded recovery succeeds.

Recovery holds the same lock, reads each bounded pending record, and searches the global ledger from its recorded prior head through a pinned head for the operation ID. If its event exists, finish index repair and mark complete. If the bounded scan reaches the pinned head without it, read current durable facts and append a new real `case.projection_reconciled` event with that operation ID and a fixed `outcome:"state_reconciled"`; then update the index and mark complete. This event reports only present-state reconciliation, never historical success or the original failure. If current state is partial/unreadable, retain pending and keep affected cases unavailable. If recovery crashes after event append, the next pass finds the same operation ID and does not append a duplicate. Operation IDs in normal and reconciliation event payloads provide idempotence evidence; real event IDs/ordinals are always generated by the ledger. Completed records may be deleted only after their completion marker and containing directory are durable.

Do not claim out-of-tree, manual, plugin, or unindexed writers are fenced by this cooperative lock. They do not participate; their behavior while live projections are active is unsupported. If deployment requires them, C-2 stays held. A shared lock cannot prove that an uncooperative writer did not change and restore bytes between observations.

Strict `case.list` is complete-or-error. A readable absent `cases/` under a readable cell root is complete-empty. Admit only exact generated and frozen legacy case directory names; missing/partial/malformed `case.json`, permission/iterator/metadata/non-UTF8 errors, unknown child names, or cap exceed makes inventory unavailable. Require `cases` and `unreadable:[]`; Go rejects missing cases or nonempty unreadable. Bound at 4,096 cases/4 MiB. The flat legacy `<root>/cases/<case-id>.json` run record is journaled as case-keyed state but is not directory membership and cannot alone create a case, head, or world. Preserve it byte-for-byte; migration does not synthesize a directory case.

`case.list` and the proposed coherent case capture each take the shared lock for their bounded local reads. Go must not hold that lock across SFWP socket calls. Therefore extend existing `case.get_overview` with an optional `capture_version=1` response that includes the case record, overview, horizon, pending approvals, scoped run summaries, and exact indexed cursor pair, all gathered under one Rust-side writer-lock acquisition. This is an additive existing-query contract, not a new verb. The Go `LiveSource.Facts` uses this one response instead of separate `ListCases`, `CaseOverview`, `CaseHorizon`, `PendingApprovals`, and `RunsListForCase` calls (`internal/projection/live.go:43-140`). Strict inventory remains its own complete locked `case.list` query. Cap the capture at 1 MiB and fail unavailable rather than truncate. This query extension and the cross-language lock protocol require exact approval; no current endpoint provides this coherent capture.

## 5. Capture identity, Store, SSE, and errors

Add `capture_digest = "sha256:v1:<hex>"` to the public snapshot, computed over Go-owned `encoding/json` bytes for the fixed snapshot struct excluding that field. Define exact field order/exclusions in the schema golden; no maps/extensions or cross-language reserialization promise. Bind required `client_capture_digest` into every non-create `InteractionIntent` stale precondition beside exact `case_id` and opaque `client_cursor`. It is untrusted stale-state input, never an authority credential. Validate it against the current authorized retained capture before dispatch. Missing/mismatched values refuse before side effects. This detects a changed capture across Go restart even when cursor is unchanged; it does not make check-to-mutation atomic or change domain authority. Preserve the narrow empty-ID/cursor create exception.

Store retains immutable serialized captures only: 64 revisions/4 MiB per case, 64 MiB total, 128 retained case heads, and 32 live streams. Each live queue is at most two frames/2 MiB; replay is at most 4 MiB and aggregate subscriptions 64 MiB including in-flight frames. These serialized-byte limits are not heap/RSS bounds. Failed range pages never advance acknowledgement. Exact `(ordinal,cursor)` duplicates dedupe; gaps invalidate only that case and require a new capture. No invalidated revision replays after a gap. Late prior-generation captures are discarded. No history is reconstructed from current Facts.

`GET /api/events?case_id=...&last=<opaque>` authenticates and validates exactly one explicit case before registration. Under the Store mutex, resolve exact cursor membership, validate readiness/gap, copy bounded replay to fixed queue, and register subscriber. Release the mutex before header/frame writes, callbacks, cancellation, or network I/O. Only then send 200/hello and flush. Unavailable or stale cursor returns typed 503/409 before headers with actual resync pair; disconnect/overflow unregisters outside blocked writes. Permit at most one already-started write after invalidation; headers and each frame have a five-second deadline. If that deadline cannot be enforced, implementation remains HOLD. A reconnect fetches the exact current snapshot, clears that case’s stale history, and retries with its real cursor/ordinal.

Stable errors: `inventory_unavailable`, `frontier_rebuilding`, `projection_gap`, `case_not_ready`, `resync_required`. Complete-empty inventory alone returns revision-3 bootstrap 200. Inventory/frontier/cap failures are 503; explicit unknown case is 404; existing case without indexed real cursor is 503; stale HTTP history is 404 and SSE resync is pre-header 409. No error maps to empty success. Startup samples pinned index head before/after strict inventory; retry at most three times then unavailable. Equal samples detect races only; they do not prove atomic inventory. A case absent a real event cursor remains quarantined. The UI validates one response arm, keeps bootstrap outside ordinary history, waits for the exact accepted case’s ready capture, and never redirects explicit selection.

## 6. Exact required approvals, verification, and limits

Before implementation, exact operator approval and authored spec/schema/ADR updates are required for: (1) the `sea-forge-case-runner` cross-process mutation/capture boundary and migration; (2) journal v1 location, records, operation IDs, recovery event, fsync/rename lifecycle and all journal caps; (3) new `case.projection_changed`/`case.projection_reconciled` event payloads and shared global append path; (4) `case.get_overview` capture response, strict `case.list`, inventory grammar and errors; (5) versioned `events.get_range`, continuation, append-ordinal decimal-string fields and index/rebuild policy; (6) `case_id`/`world_id` schemas, `cursor_ordinal`, `capture_kind`, capture digest and intent precondition; (7) Go Store/SSE readiness, HTTP codes, all byte/count/deadline limits; and (8) revision-3 bootstrap wiring, including its create-only schema exception. No dependency, new kernel verb, synthetic identity/cursor, second authoritative history, preflight removal, authority bypass, or fabricated historical capture is proposed.

| Boundary | Required positive and negative evidence after approval |
|---|---|
| Writer journal | Every listed writer emits one real operation-ID event after durable writes; crash at each pending/write/append/index/complete boundary recovers once. Partial state, full journal, lock timeout, or publication failure never returns ready/success. |
| Capture/inventory | Captures use one existing-query call under the Rust writer lock; concurrent supported mutation yields before-or-after state, never a mixed response. Every filesystem/list failure, unknown child, missing record, cap, or changed head is unavailable, never empty. |
| Range/index/restart | Append order and exact IDs survive concurrent appends, dropped/reordered broadcast, restart, stale/corrupt/behind/ahead index, torn tail, oversized row, invalid continuation, and rebuild ceilings. No index-ahead readiness. |
| Stale intent | Same cursor with changed digest refuses before dispatch; exact current digest proceeds only to existing authority/domain guards. Missing/mismatched digest and bad cursor fail closed. |
| Store/SSE/UI | Exact-case replay registers before writes; gaps/overflow/incomplete state fail before 200; no store lock during writes. Resync uses real capture; bootstrap/create never fabricates history or changes explicit selection. |

Current limitations are binding: no atomic transaction spans all domain side effects and current Facts; check-to-mutation remains non-atomic beyond existing authority/domain checks. Captures are honest current observations, never historical reconstruction. The shared lock covers only cooperative in-tree writers, not manual or out-of-tree actors. The source inventory is a bounded migration list, not proof that all runtime writers participate. V4, no-case success, schemas, Store/SSE changes, and implementation all remain held pending root architecture review, a fresh independent review, exact operator approval, and actual focused/canonical verification.
