## 2. Versioned bounded frontier

Extend existing SFWP `events.get_range`; add no kernel verb. Optional `range_version=2` selects paged output; omission retains current shape but uses bounded reading; unknown versions fail typed. Pages carry ordered frames, exact `head:{cursor,cursor_ordinal}`, scanned ordinal, continuation, completion flag, and optional case `case_state_stamp`. Ordinal/epoch are canonical checked-u64 decimal strings (client `BigInt`); cursor stays opaque. Continuation binds stream, pinned head, last complete row/cursor, byte offset, and checksum; validate its prior row before seeking. Bad token, torn row, or bad tail fails without partial completion.

Current `get_range` reads all entries before its 500-frame cap (`crates/sea-forge-server/src/sfwp/events.rs:169-208`; `crates/sea-forge-ledger/src/types.rs:784-801`). Replace it with bounded line/offset reading under the existing lock: at most 500 scanned rows, 500 frames, 1 MiB response, 50 ms lock wait; reconciliation at most two pages/500 ms per scheduling turn. Oversized rows and lock timeout are typed errors.

Add derived `case-head-index-v1` (never history): exact global head, latest exact pair per case, version/checksum, resumable repair position; cap 4,096 cases/8 MiB. Append is authoritative; atomically sync index before broadcast. Missing, ahead, corrupt, mismatched, or behind index stays unavailable until paging reaches real pinned head. Rebuild cap per lineage is 1,000,000 rows or 10 minutes active work; retain continuation and `frontier_rebuilding`, never reset automatically. Broadcast is only a wake hint; paging repairs drops, reordering, and restart gaps.

## 3. Journal, epoch, and recovery

Add versioned derived state at `.sea-forge/case-projection-journal/v1/`, including one cell-scoped OS file lock and checked `u64` `state_epoch`. All supported facts writes use this lock. Rust-side stamp reads use the same lock only for local file/index reads. Go never takes a client-owned lock or holds a lock across SFWP/network calls. The ledger append keeps its separate lock (`sea-forge-ledger/src/types.rs:701-723`); lock order is projection lock then ledger lock, never reverse. Use pinned Rust 1.92 `File::lock`; no new dependency. Authenticate/authorize and run existing guards before journal effects. No auth callback, network I/O, or capability execution under the projection lock; hold it only for bounded durable write transitions, with long execution outside and each persisted transition separately journaled.

For each transaction, allocate an operation ULID using existing `sea-forge-ledger::types::ulid` (`types.rs:93-148`). Record version, exact IDs, fixed mutation class, already-authorized caller classification, prior ledger ordinal, operation ID, epoch, and `pending`; no credentials, arbitrary payload, or raw error. Cap each record at 32 KiB, the entire journal at 256 records/8 MiB, and lock wait at 50 ms. Before adding pending, prune completed records only; if pending records fill the cap, refuse before visible writes. Under the projection lock, checked-increment epoch and durably publish pending **before** case writes (never wrap/reset). Sync temp file, atomic rename, parent directory. Then write case/local ledgers, append real global event with operation ID (`case.projection_changed` where no semantic event exists), and update index. Atomically replace pending with a clean completion record at the next checked epoch and sync directory. This replacement alone makes state clean.

Recovery holds the same lock and scans from prior ordinal to pinned head for the operation ID. If found, finish index repair. If absent after a complete bounded scan, read current state and append a real `case.projection_reconciled` (`outcome:"state_reconciled"`), then index it. This reports present-state reconciliation, not historical success. Partial/unreadable cases remain pending/unavailable. Recovery after append finds the same ID, avoiding duplicates. Full pending journal remains unavailable until recovery.

Manual, plugin, out-of-tree, and unindexed writers do not share the lock and remain outside the guarantee; C-2 stays held if they may write live. Change-and-restore between observations is undetectable.

## 4. Stamped coherent Facts capture

Go `LiveSource.Facts` joins `ListCases`, `CaseOverview`, `CaseHorizon`, `PendingApprovals`, and `RunsListForCase` (`apps/godspeed-casework-go/internal/projection/live.go:43-140`); individually locked views are not a transaction. Add V2 `events.get_range`/status field `case_state_stamp:{state_epoch,case_dirty,head:{cursor,cursor_ordinal}}`. Rust reads durable epoch/pending state and real case head under shared lock, unlocks, then replies.

Go brackets those existing authorized reads with clean stamps, without holding a filesystem/Store mutex during RPC. Accept only equal epochs and exact case head/cursor/ordinal with both clean. Otherwise discard partial Facts and retry at most three times, then typed unavailable. Supported mutation advances epoch before writes or leaves dirty, and advances it again on completion/recovery. A post-final-stamp mutation can stale the capture; event delivery and intent/domain checks still apply. This is a coherent supported-writer interval, not atomic later disclosure or external-writer exclusion. Epoch is not event ID, revision, authority, or loss counter. Persisted/wire fields require approval.

`case.list` is complete-or-error: readable absent root means complete-empty; admit exact generated/legacy case directory names only. Unknown children, non-UTF8, I/O/iterator/metadata error, missing/partial/malformed `case.json`, or cap exceed is unavailable. Require `cases` and `unreadable:[]`; Go rejects missing cases/nonempty unreadable. Cap 4,096 cases/4 MiB. Flat legacy `<root>/cases/<case-id>.json` is journaled case-keyed state, not membership; it alone cannot create a case/head/world. Preserve bytes; never synthesize a directory case. Bootstrap samples pinned head around inventory, retries three times, then fails closed; matching samples detect races only.

## 6. Capture identity, Store, SSE, and errors

Add `capture_digest="sha256:v1:<hex>"` over Go `encoding/json` bytes of the fixed snapshot struct excluding the digest; schema goldens define order/exclusions; no maps/extensions or cross-language reserialization promise. `capture_kind` is `process_baseline` or `event_capture`. Require `client_capture_digest` on every non-create intent beside exact case ID/cursor. It is an untrusted stale precondition, not authority; validate against the current authorized capture and refuse missing/mismatch before effects. This distinguishes same-cursor restart captures, not check-to-mutation races. Preserve create-only empty IDs and current authority.

Store bounds: 64 revisions/4 MiB per case, 64 MiB total, 128 case heads, 32 live streams; queue ≤2 frames/2 MiB, replay ≤4 MiB, aggregate subscriptions ≤64 MiB including in-flight. Serialized-byte limits are not RSS guarantees. Failed pages do not ack. Dedupe exact pairs; invalidate only gapped case and require new capture; never replay invalid history or reconstruct from current Facts. For `/api/events?case_id=...&last=<opaque>`, authenticate/validate one case; under Store mutex check readiness/cursor, copy bounded replay, register; release before callbacks, cancellation, headers, or network writes. Error/resync is typed 503/409 before headers with actual pair. Then send 200/hello. One started write may finish after invalidation; header/frame deadline 5s. Unprovable deadline or overflow/disconnect is HOLD/close; resync fetches exact current snapshot and clears only that case.

Typed outcomes: `inventory_unavailable`, `frontier_rebuilding`, `projection_gap`, `case_not_ready`, `resync_required`. Complete-empty alone returns revision-3 bootstrap 200. Inventory/frontier/cap errors are 503; explicit unknown case 404; existing case lacking real indexed cursor 503; stale HTTP history 404 and SSE resync pre-header 409. Errors never become empty success. UI validates one response arm, keeps bootstrap outside history, waits for exact accepted case readiness, and never redirects explicit selection.
