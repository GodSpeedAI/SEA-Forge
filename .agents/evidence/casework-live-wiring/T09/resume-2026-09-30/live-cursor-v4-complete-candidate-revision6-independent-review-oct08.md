## Blocking gaps

**1. Legacy events.get_range completion at the scan cap is unspecified.** Revision 6 §2 says omitted range_version preserves the old response shape while using a bounded reader; its v2 contract limits each request to 500 scanned rows, but it gives no continuation or completion field for the old shape and no explicit rule for the legacy call when 500 rows are exhausted before the requested range is complete. Existing get_range returns Result<Vec<EventFrame>, ForgeError> and filters the entire read_entries() list before applying the event-frame limit (events.rs:169-208; LedgerStream::read_entries, types.rs:785-802). With sparse event rows, a 500-row scan may contain fewer than the requested frame cap while later matching events remain. The candidate must state that legacy mode never returns a successful partial vector as complete—e.g. return a typed unavailable error when bounded scanning cannot prove completion—or provide a compatible continuation mechanism. It must also name the caller behavior. Otherwise “bounded reader” and preserved legacy semantics can silently conflict.

**2. The required checked TypeScript BigInt ordinal contract is missing.** Root decisions explicitly select canonical decimal-string u64 ordinals and checked BigInt behavior. Revision 6 §2 says only that v2 append_ordinal is a canonical decimal string; §1 notes existing numeric-cursor schema conflicts, and §5 lists decimal ordinal schema approval, but it never defines the public TypeScript representation/validation or how comparisons preserve the full u64 domain. The earlier revision-2 contract specifies canonical grammar, upper bound 18446744073709551615, string alias, and BigInt for comparisons; Number and lexicographic ordering are prohibited. Carry that contract forward, or explicitly state that clients treat the ordinal as opaque and never compare it. As written, the wire format is named but the approved cross-language precision guarantee is incomplete.
