## 1. Preserved contracts and actual identities

Preserve bootstrap revision 3 exactly: a ready `{snapshot: ...}` arm or mutually exclusive `{bootstrap:{status:"no_cases",timestamp,perspective,templates}}`. Bootstrap has no case/world ID, cursor, revision, or history. Its timestamp is actual response capture time, perspective is session-verified, and templates are the existing canonical entry options. It is an as-of observation, not an atomic no-case interval. No-case success remains disabled until complete inventory and journal cleanliness are proven. Preserve preflight and `PROPOSE_CASE`; only the returned real case ID can proceed, and only after that exact case has a validated ready snapshot may history or SSE mount. Explicit case selection never redirects. Only an absent case query can choose default/bootstrap. A nonempty `cursor` selects retained history; absent or empty cursor takes the live path (`server.go:188-230`).

Preserve IDs byte-for-byte. Generated case IDs are `case_YYYYMMDDTHHMMSSZ_<6 lowercase hex>` (`crates/sea-forge-core/src/ids.rs:6-10,32-47`); the frozen legacy grammar is `case-[a-z0-9_.-]+`. World ID is the stable exact `world-<case_id>` value (`apps/godspeed-casework-go/internal/projection/builder.go:99-104`). Cursor is the exact opaque ledger `entry_ulid` (`crates/sea-forge-server/src/sfwp/events.rs:19-24,61-89`); durable append ordinal, not lexical cursor order, establishes sequence. No normalization or synthetic cursor is permitted.

The current schema and producers conflict: case/world patterns and numeric cursor assumptions in `cognitive-world.schema.json:19-37` do not match generated IDs and ledger cursors; `PROPOSE_CASE` is also absent from the intent schema despite its narrow create-only empty-ID path (`interaction-intents.schema.json:7-56`; `proposals.ts:60-80`; `intents.go:154-196`). Amend authored Rust/Go/TypeScript/schema contracts together only after exact operator approval. Preserve D-2 verified identity, delegation allowlist, dual-principal audit, SoD, CSRF, rate limit, and existing authority/domain checks.

## 2. Bounded event frontier and shared journal

Extend existing `events.get_range`; add no kernel verb. Optional `range_version=2` selects a page response; omitted version preserves the old response shape but uses a bounded reader; unknown versions fail typed. A v2 page contains ordered frames with exact cursor and canonical decimal-string `append_ordinal`, a pinned exact head pair, `scanned_through_ordinal`, continuation, completion flag, and optional `case_state_stamp`. Continuation binds stream, pinned head, last complete row/cursor, byte offset, and checksum; verify its prior full row before seeking. Each request scans at most 500 rows, returns at most 500 frames and 1 MiB, and waits at most 50 ms for the ledger lock. Torn/oversized rows, bad tail/token, timeout, mismatch, or cap exceed return typed unavailable with no partial-complete marker. Reconciliation gets at most two pages or 500 ms per scheduling turn. All these existing ceilings remain in force during repair.

The page validates **every complete global ledger row** from the verified continuation/frontier through its pinned head before filtering event frames. Check checked-successive global append ordinals, exact row cursor identity, the preceding continuation row and checksum, and pinned-head identity. Initial scans prove continuity from the ledger's actual origin; resumed scans validate the prior complete row before seeking. Non-event rows advance `scanned_through_ordinal` but never become event frames. An empty filtered event array may still carry real global progress. Bind continuation to the last fully validated row's exact cursor and ordinal. Never claim completion from a filtered event count, partial row, or failed page.

Replace current `get_range` materialization of all `read_entries()` before its frame cap (`crates/sea-forge-server/src/sfwp/events.rs:169-208`; `crates/sea-forge-ledger/src/types.rs:784-801`). Add a derived `case-head-index-v1`, never authority/history, capped at 4,096 cases/8 MiB. It stores exact global head and latest real case cursor/ordinal pairs, version/checksum, and resumable repair position. Missing, corrupt, ahead, behind, or mismatched index stays unavailable until repaired from complete ledger pages to a pinned real head. Per detected lineage, rebuild is capped at 1,000,000 rows or 10 minutes active work; preserve continuation and `frontier_rebuilding`, do not reset the ceiling automatically. A latest-head index cannot identify the owner of an absent row or prove global continuity.

`LedgerStream::append` remains the durable ordering authority. Under the projection-writer lock, append to the existing ledger (which takes its own lock), advance and durably replace the derived index, then broadcast through `ServerState::publish_event`; broadcast remains only a wake hint. A crash after ledger append but before index replacement leaves pending/behind state for restart repair, never a falsely current head. Startup pins a ledger head, validates/resumes index repair and strict case inventory, and only then establishes case baselines. If the head or inventory changes during bounded reconciliation samples, discard partial readiness and retry at most three times; otherwise return typed unavailable. Events after the accepted head are delivered through ordinal paging, not by claiming the baseline is an atomic no-case interval.

The Go reconciliation owner maintains one **validated global scan frontier**, distinct from every per-case head and delivery watermark. It accepts a page only for the expected continuation and pinned head, acknowledges only fully validated global progress, and distributes validated event frames by exact case ID. A case watermark may skip many global ordinals because other cases and non-event rows occupy them. Broadcast is only a wake hint: duplicate, missing, or reordered hints never advance either acknowledged frontier. Repeated exact ledger pairs are duplicate deliveries; inconsistent cursor/ordinal identity in the authoritative global scan is a global integrity failure.

Propose a shared case-projection journal under `.sea-forge/case-projection-journal/v1/`, in `sea-forge-case-runner` (already shared by CLI/server and dependent on `sea-forge-ledger`). It has one cell-scoped OS writer lock and checked `u64` state epoch. Acquire it before the ledger append lock, never in reverse. Authenticate/authorize and run existing guards before journal effects. No auth callback, network I/O, or capability execution under the lock; long work stays outside and each persisted transition is separately journaled.

Before a case-visible write, durably publish a pending record and increment epoch; record version, exact IDs, fixed mutation class, already-authorized caller class (`cli_actor`, `verified_gateway_user`, `verified_gateway_agent`, `supervisor`, or `migration`), operation ULID, prior global ordinal, epoch, and pending status, never credentials/raw error/arbitrary payload. Reuse the visible `pub fn ulid` in `sea-forge-ledger::types` (`crates/sea-forge-ledger/src/lib.rs:5-6`; `types.rs:93-148`); no new dependency or identifier authority is needed. Cap a record at 32 KiB, journal at 256 records/8 MiB, lock wait at 50 ms. Prune only durable completed records; if pending entries fill the cap, refuse before visible writes. Use synced temp, atomic rename, and parent-directory sync. Apply the existing case/local-ledger writes, append a real safe global event carrying the operation ID (`case.projection_changed` where no semantic event exists), update the index, then durably publish clean completion at the next checked epoch. Overflow never wraps.

On restart, any pending record keeps its affected case unavailable. Persist recovery scan state: operation ID, exact start/prior ordinal and pinned-head pair, next byte offset, last complete row cursor/ordinal, and scan version/checksum. Each bounded step validates full rows and advances this continuation durably. Finding the operation event is not sufficient by itself: validate current durable case state, repair the derived index, and complete only if both are valid; otherwise remain pending/unavailable. **Absence is established only after a validated global scan reaches the pinned head.** A partial, unreadable, corrupt, timed-out, or over-budget scan remains pending and unavailable; it cannot emit a reconciliation event or clear the marker. After complete absence only, read and validate actual current state, append a new real `case.projection_reconciled` event with `outcome:"state_reconciled"`, update the index, then mark complete. This reports present-state reconciliation, never historical success. Crash after append is idempotent: the next scan finds the same operation ID. Hitting recovery/rebuild work ceilings preserves pending/continuation and requires operational review, not an automatic reset.

Any pending journal operation, including one whose case directory has not yet been created, blocks complete-empty/bootstrap success. Inventory checks journal cleanliness under the same bounded local lock/read protocol. A flat legacy case-keyed file alone does not create a directory member, but a related pending operation still blocks empty success. Cooperative locking does not fence manual, plugin, out-of-tree, or external processes; if such writers may be active, affected live projection remains held/unavailable.

## 3. Capture and migration boundary

Go `LiveSource.Facts` currently joins `ListCases`, `CaseOverview`, `CaseHorizon`, `PendingApprovals`, and `RunsListForCase` (`apps/godspeed-casework-go/internal/projection/live.go:43-140`). Individually locked calls are not one capture. Extend existing `events.get_range`/status with bounded `case_state_stamp:{state_epoch,case_dirty,head:{cursor,cursor_ordinal}}`. Rust reads actual durable epoch/pending state and case head under the common lock, then releases before replying. Go brackets its existing authorized reads with clean stamps, accepts only equal epochs and identical real case head pairs, discards partial Facts on mismatch, retries at most three times, then returns typed unavailable. A post-final-stamp mutation may stale the capture; this is a supported-writer interval, not atomic later disclosure or external-writer guarantee. No lock spans RPC.

`case.list` is complete-or-error: readable absent root is complete-empty only if the journal is globally clean. Require `cases` and `unreadable:[]`; accept only exact generated/legacy directory grammars. Unknown children, non-UTF8 names, I/O/iterator/metadata errors, missing/partial/malformed `case.json`, journal pending state, or limits are unavailable, never empty. Cap inventory at 4,096 cases/4 MiB. Flat legacy `<root>/cases/<case-id>.json` is not membership. Bootstrap samples pinned head around complete inventory, retries three times, and then fails closed; matching samples detect races but do not claim atomic empty time.

## 4. Capture digest, history, SSE, and Store

Add `capture_kind` (`process_baseline` or `event_capture`) and `capture_digest="sha256:v1:<64 lowercase hex>"` to ordinary snapshots. Define V1 preimage as the bytes returned by `json.Marshal` on a fixed Go struct with exactly this declaration/JSON order: `world_id`, `case_id`, `cursor`, `cursor_ordinal`, `timestamp`, `capture_kind`, `perspective`, `summary`, `visible_objects`, `available_actions`, `attention_focus`. `capture_digest` is excluded by using a dedicated digest-preimage struct; no other field is excluded. Nested declaration/tag orders are fixed as follows: `ActorPerspective(actor_id, role, display_name)`; `WorldSummary(headline, phase, status_phrase, progress_percent)`; each `CognitiveObject(id, kind, name, status, badge, explanation, salience, parent_id, depends_on, spatial_layout, actions)`; `SpatialLayout(x, y, z, radius)`; each `ActionDescriptor(id, label, intent, variant, consequential, requires_justification)`; `AttentionFocus(primary_object_id, salience_rank, narration)`. V1 permits no maps or extension fields. Use `json.Marshal`, not `Encoder` (no newline); preserve Go's defined escaping, null/empty and `omitempty` behavior. Golden tests pin the complete exact bytes and resulting SHA-256 for nil/empty optionals, Unicode/HTML-sensitive strings, decimals, and populated nested arrays. Digest failure prevents readiness. Clients treat the value as opaque bytes/string: they compare the received value exactly and echo it, never compute JCS or reserialize to verify. The digest is a capture identity, not cursor, authority, event, or historical reconstruction.

Every non-create intent requires `client_capture_digest` beside exact `case_id` and opaque `client_cursor`; it is untrusted stale-precondition input. Validate against the current authorized retained capture and refuse a missing/mismatch before effects. It does not make check-to-mutation atomic or alter existing authority.

For `GET /api/world?case=<id>&cursor=<opaque>`, require `capture_digest=<exact digest>` for that exact cursor. Missing, wrong, evicted, or mismatched pair never returns a different capture at the same cursor. Before any partial/body response, return typed `resync_required` 404 with only an actual current retained boundary `(cursor,cursor_ordinal,capture_digest)` for that case; if no such boundary exists, return typed 503 unavailable. Current-world GET without historical cursor returns only a validated current capture.

For `/api/events?case_id=<id>&last=<opaque>&last_capture_digest=<digest>`, preserve exact cursor in SSE `id:` and bind digest separately. Atomically under Store mutex validate readiness and exact pair, copy immutable replay, charge its bytes, and register a separate live queue; release mutex before callbacks, cancellation, headers, or network writes. Unknown/missing/mismatched/evicted pair yields pre-header typed `resync_required` 409 with a real retained boundary; unavailable boundary or budget/readiness failure yields typed 503. No 200/hello precedes successful admission. The adapter owns reconnect state and sends both values; native browser Last-Event-ID alone is insufficient. On 409, client clears only that case's history/cache, fetches its actual current snapshot, then reconnects using that snapshot's exact cursor/digest. It never fabricates a cursor or silently resumes at a different capture. Preserve the single already-permitted in-flight write residual and bounded 5-second header/frame deadline; no network I/O/cancel/join under Store mutex.

Caps: maximum individual snapshot or event is 1 MiB; at most 64 revisions per replay and 4 MiB replay bytes; 64 revisions/4 MiB retained per case; 64 MiB Store retention; 128 case heads; 32 streams; two live frames/2 MiB per queue; 64 MiB aggregate subscriptions including replay, queues, and in-flight writes. These serialized-byte limits are not RSS guarantees. Never truncate/drop while claiming continuity. A case delivery watermark may skip intervening global ordinals; it is not a global scan acknowledgement. Failed pages do not acknowledge global or case progress. Dedupe exact `(ordinal,cursor)` pairs. Never rebuild historical frames from current Facts.

## 5. Errors, approvals, and verification gate

For Store ingestion, validate each real frame's opaque cursor and ordinal pair, case identity, bounded serialized size, and capture digest before admission. Establish global continuity independently of case routing: every authoritative page must prove each global row from the expected continuation through the pinned head, including non-event rows, before its event frames are filtered/distributed. The only global acknowledgement is the last fully validated `scanned_through_ordinal` bound to its exact row cursor and pinned head. A page with no matching case events may still advance that global scan frontier if its complete rows validate. It may not advance any case watermark without a validated frame for that case. Exact repeated ledger pairs are duplicate deliveries; duplicate/reordered wake hints do not acknowledge anything.

If a global row is missing, unreadable, malformed, discontinuous, has inconsistent cursor/ordinal identity, or has a bad continuation/head binding, its case impact is unknown. Do not advance either frontier from the failed page. Mark ordinary live projection and dependent bootstrap unavailable, stop readiness for dependent streams, and drain those streams; retained bytes remain within caps but cannot be served as ready current state or successful replay until global coverage is proven again. A derived per-case head index cannot attribute an absent row. Restore readiness only after bounded repair validates complete global coverage to a real pinned head, repairs/checks the derived index, and revalidates strict inventory and journal cleanliness. If that proof cannot complete within existing cumulative ceilings, remain unavailable for operational review. A real global resource-ceiling exhaustion is global unavailable, not an isolated case gap.

Only after global continuity is proven may a failure be case-local, and then only when validated metadata identifies its case. Examples are an authorized capture that cannot be retained, a dirty case journal marker, or an unavailable/evicted retained capture pair. Invalidate that case's current readiness/history and drain only its streams; other independently validated cases may continue. A later actual stamped capture at that case's real indexed head can establish a new current boundary, without reconstructing old history. Do not infer a missing row's case from spacing between that case's ordinals or from the latest-head index.

SSE admission under the Store mutex checks both global readiness and one authenticated explicit case's readiness, retained boundary and digest; it then copies bounded replay (at most 64 revisions/4 MiB) and registers a separate live queue (at most two frames/2 MiB). Replay is sent first and never inserted into that live queue. Admission charges replay, queue, and any in-flight serialized payload against the aggregate 64 MiB subscription budget and 32-stream limit. On global integrity failure, prevent new admissions and drain dependent streams. On a proven case-local failure, drain only that case's streams. Mark/remove subscriptions under the mutex, then signal cancellation after unlock. No callback, cancellation, join, header, or network write occurs under the Store mutex. Only after successful admission may the handler write `200` and hello; one response writer sends replay then live frames. Enforce a 5-second deadline per header/frame. At most one already-permitted write of at most 1 MiB may complete after invalidation; issue no later permit. If the HTTP stack cannot enforce bounded writes/cancellation, keep implementation held.

The client validates one response arm. Bootstrap stays outside history, cursor caches, trajectory, and SSE. A bootstrap refresh is authenticated, serialized, starts at least one second after the prior refresh, aborts on disposal/session change/transition, and ignores stale completion; errors remain errors, never empty success. Reuse the canonical template mapper for `/api/templates` and bootstrap: preserve ordering/optionals, map wire `type` to app `param_type`, absent `required` to false, and existing default conversion. After accepted create, retain only the returned actual ID, wait boundedly for a validated ordinary snapshot of that exact case, then load history/mount the app/attach SSE. Timeout remains accepted-but-not-ready; never issue a second create or redirect an explicit selection. A resync clears only the affected case and fetches its actual current snapshot before reconnect. Global readiness loss makes the dependent projection unavailable; do not clear unaffected case identities or claim their histories were revalidated until global coverage is restored.

Keep typed failures `inventory_unavailable`, `frontier_rebuilding`, `projection_gap`, `case_not_ready`, `resync_required`. `projection_gap` must distinguish unknown-impact global integrity/coverage failure (cell-wide unavailable/drain) from a proven case-local capture/history failure. Complete-empty alone may return bootstrap 200. Inventory/frontier/cap/global-coverage errors are 503; explicit unknown case 404; existing case without real indexed cursor 503; historical GET resync 404 and SSE resync 409, both before body/headers. Errors never become empty success. A failed/incomplete page never advances acknowledgement.
