# Private manager combined-image decisions

Root decisions for independent design review. These supplement the combined
image proposal and lifecycle preregistration; they do not release source work.
Public V4, Next, SSE, schemas, authority and dependencies remain outside scope.

1. Keep the pure helper unchanged. The manager-owned canonical wrapper is the
   final publication budget. Its exact ordered shape includes constant schema,
   always-present one-digit phase and initializer-result controls, and either
   the exact nil-current key or raw canonical helper image. Encode the key once.
   Never install a candidate that only passes the helper's smaller image check.
2. Initial failed/unretainable/invalid selected reads count as A, appear in no
   Runs row, and yield the normal unavailable initial DTO with all successful
   list counts present. They do not fail the whole Prepare. No accepted value
   is synthesized. Publish a fixed generic initializer result, bar further
   starts for that failed initializer, close ready outside the lock, and let
   the actual worker return/close workerDone. Each waiter releases its own
   failed attachment and joins any teardown it owns outside the mutex. Shared
   waiters still receive that one result. No no-current retrying attachment is
   returned as a recoverable observed run; recurring recovery applies after
   an accepted current value exists. Auth/guard/cancellation/stop/irreducible
   full-DTO assembly remain typed error, zero wrapper, nil lease plus rollback.
3. Reject an oversized nil-current key image before retaining the new poller,
   acquiring its reference, or starting trace work. Count A, not C. Capacity
   refusals remain C. Do not disclose the rejected key in errors or logs.
4. A unique manager-owned entry object and its sole worker can serve as the
   initializer publication token. Recheck exact map-entry identity, admissible
   phase, and captured prior pointer at publication. Removal/recreation requires
   actual worker JOIN first. Do not conflate helper accepted-version Generation
   with initializer identity. This intentionally replaces the illustrative
   scalar token shape in the addendum; the critic must verify equivalent stale
   completion protection. Add a scalar only if an actual allowed path needs it.
5. Runtime contexts, channels, timers, dependency pointers and reference maps
   are synchronization/ownership primitives outside serialized retained-value
   accounting. Enforce 16 cohorts, 16 pollers and 128 attachments under the
   actual manager mutex. Any additional retained scalar/value-bearing publisher
   control introduced by implementation must be encoded exactly once with
   fixed width. No heap/RSS bound follows from these image and count caps.
6. Later combined-image refusal discards every candidate-derived field. With
   an accepted prior value, preserve its entire ledger/window/metadata and
   publish only its fixed marker copy. Nonterminal refusal can recover through
   a later complete fitting candidate; terminal refusal sets terminal-retention
   availability and stopping phase atomically before any JOIN. Generation
   overflow similarly bars scheduling. Marker changes must preserve length at
   the exact combined boundary, including both outer controls and inner image.
7. Add the proposed new manager-retained-image fixture only after independent
   design approval and a separate test-first release. Existing manageraf2df,
   base34df and policy4c70 fixtures stay exact. Cover nil image, exact combined
   cap, +1 refusal/prior atomicity, oversized nil key/no read, control widths,
   and pointer-token guards. A direct stale-map defensive unit is not proof
   that a permitted replacement can race an unjoined worker; lifecycle tests
   must separately prove JOIN-before-reuse and shared initializer survival.

All selected initializers must be reserved and launched before waiting on the
first. No adapter, callback, cancellation, channel send/close, wait or JOIN is
allowed under the actual mutex. The worker waits at least one second after a
completed read before starting another; no retained polling timestamp is needed.
Initial DTO hydration uses its existing separate helper once after watermark
capture. No placeholder lifecycle or public integration is approved here.
