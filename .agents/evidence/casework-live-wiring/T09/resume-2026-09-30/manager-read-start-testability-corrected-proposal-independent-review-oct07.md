## Approved design elements

- `claimPollerReadStart` is a real production linearization point under the same manager mutex used by Stop and final-ref release. It checks open admission, exact map identity, readable phase, and eligible refs; it performs no port call, callback, cancellation, signal, wait, or join. Logical `ReadsAttempted` increments only at the actual `ReadRunTrace` invocation, consistent with the original count rules and preregistration's no-I/O/no-cancel/no-wait-under-lock invariant.
- The root worker-launch clarification is reflected: `reservePollerBatch` returns the creator's immutable launch list; `prepare` launches every owned entry exactly once outside the mutex before any wait or return/rollback; Stop may transition/cancel during the reservation-to-launch interval but waits outside the mutex for creator operations and workers; the creator finishes its operation before waiting on a drain that includes itself. This preserves reserve-all-selected-before-wait/all-eight-start-before-wait and avoids self-join.
- The claimed-then-canceled-before-port-call branch now returns existing initializer code 4, phase 2 or 3, nil current, ready once, zero actual reads, typed failed-Prepare result, and workerDone/JOIN completion. An actual call remains owned through return/retirement and JOIN. This closes prior review 2a00's missing outcome without changing count semantics.
- `runPollerFromClaim(entry, eligible)` is a defensible private worker continuation for deterministic ordering. The proposal gives it real production work: `runPoller` must always pass the result of `claimPollerReadStart` into this exact continuation, which owns the actual read/result/readiness/completion path. Tests sequence the same two production methods to interpose Stop, not an injected callback or fake pre-call port barrier. Implementation review must verify the production call site is mandatory and there is no alternate runtime continuation; otherwise a test direct-call could prove a path runtime does not use.
- The methods and fields stay private; no public API, JSON field/code, policy bound, dependency, manager fixture, or pure helper is changed. All-eight-start-before-wait is explicitly preserved.

## Remaining material gaps

1. **Cohort-cap reservation before list/read is not specified.** The original Unit 1 assignment and preregistration require preparing cohorts to count toward the 16-cohort limit and require atomic lease/cohort reservation before list/read work. The corrected method description says `beginPrepareOperation` registers a creator operation before reservation, but does not state that it reserves the cohort slot; `reservePollerBatch` receives selected rows and therefore appears after list/selection. The plan must state which production transition reserves the cohort slot before any list/read and how Stop/cancellation owns that reservation. Operation registration alone does not satisfy capacity admission.

2. **The combined fixture matrix omits two prior required A cases.** The still-active failure-fixture assignment requires (a) shared real first-read failure to be successful A for each Prepare, with distinct owner/waiter `ReadsAttempted` counts and per-lease ref cleanup, and (b) an oversized nil-current key to be classified by the manager as A with no poller entry/ref/read. The corrected seven-case matrix adds the new worker ordering cases, shared-stop/cancellation/ref ownership, detach/A race, and all-eight preservation, but does not state either required A test. The pure encoder test proves serialization refusal only; it cannot prove manager admission, A/C counts, or zero poller creation. These cases must remain in the combined fixture plan or be explicitly assigned to another already-approved manager fixture; no such coverage is present in the cited frozen suite.

3. **`stopAndDrain` cancellation wording conflicts with the lock rule.** The proposal says it “sets `stopping` and snapshots/cancels under the lock, then cancels ... outside it.” The lifecycle preregistration prohibits cancellation under `m.mu`. Clarify that the locked section snapshots cancel functions/state only and invokes every `cancel` after unlocking. No interpretation may call `cancel()` while the mutex is held.

## Material differences from prior direction

The corrected proposal materially adds an operation `sync.WaitGroup`, an immutable owned launch batch, the private `launchPollerBatch`, and the runtime-used `runPollerFromClaim` continuation; these additions are supported by the root clarification's launch guarantee and the testability need. It does not add a fake callback, test-only field, persistent claim token, extra worker, serialized state, or read counter. The root's accepted mutex linearization semantics remain intact: Stop winning the mutex prevents the claim; a winning claim may still enter the port after Stop's wall-clock request; the actual call alone increments read counts. Current key/fixture identities are reconciled correctly.

## Limits

This is a source-only proposal review. No source, fixture, formatter, test, compiler, scanner, Git mutation, or runtime work was performed. The core eligibility/launch design is approved, but the complete Unit 1 implementation/test release should wait for the three bounded clarifications above and an updated combined fixture matrix. The actual implementation still requires independent review of the mandatory runtime call path, all-eight launch behavior, cancellation/readiness, operation completion before join, and unchanged frozen sources.
