## Existing guards and exact gaps

- Production `httpCaseworkAdapter.ts:78-80` has a suitable `isRecord` object guard. Existing `isArtifactPayload` (`:82-100`) demonstrates property checks and literal `Set` allowlisting; `isTemporalCheckpoint` (`:110-127`) demonstrates bounded integer and relation checks, but uses `Number.isInteger`, not safe-integer validation, and only checks timestamp type.
- The exhaustive observation shape validator currently exists only in test code: `apps/godspeed-cognitive-ui/src/ports/wireContract.test.ts:203-221,405-440,489-569`. It uses `Number.isSafeInteger` plus nonnegative checks (`:410-411`), exact-key checking (`:492,501,519,534,558`), and `oneOf(readonly literal list)` guards (`:416-440`) for the event, frame, statuses, standings, and observation states. Compile-time pins tie those lists to canonical type unions (`:227-242,328-370`). These helpers are test-local, not exported runtime validators.
- The test validator verifies the individual run frame counts are safe integers and then compares `total === retained + omitted` (`:544-552`); it does not separately prove that the computed sum remains a safe integer. The cohort count fields are individually checked and optionality is conditioned on `run_list_state` (`:499-515`), but cross-count equations are not asserted there.
- Current observation timestamps in `wireContract.test.ts:494-505,537-539,559` are checked only as strings. No UI runtime RFC3339Nano calendar validator was found. Go emits/accepts RFC3339Nano using the standard library (`internal/server/feed.go:21-39`, `internal/server/trajectory.go:121`); `time.Parse(time.RFC3339Nano, ...)` is the exact available calendar-aware reference. The HTTP parser currently substitutes `new Date().toISOString()` for absent timestamps (`httpCaseworkAdapter.ts:546`), which cannot be accepted as observation validation.
- The test-only `CURSOR_RE = /^\d+\.\d+$/` (`wireContract.test.ts:416`) is used by legacy cognitive snapshot/fixture checks and the current observation fixture (`:494,609`). In contrast, the Go event feed documents the source cursor as the kernel `entry_ulid` (`internal/server/feed.go:21-23`), and the UI TS observation type calls it the latest real case cursor. Treat the cursor as opaque/nonempty unless the boundary explicitly resolves this shape discrepancy; do not blindly reuse the epoch-dot-sequence regex on the live event.

## Ingestion and callback seams

- `HttpCaseworkAdapter.subscribeEvents` is the shared entry (`apps/godspeed-cognitive-ui/src/adapters/http/httpCaseworkAdapter.ts:297-377`). Native `EventSource` registration is an explicit four-name allowlist at `:358-360`; it currently omits `execution_observation`. Each event goes through `parseStreamEvent` at `:340-343`, then the monotonic cursor comparison at `:344-347`, before delivery/update at `:348-356`.
- Fetch-streaming ingestion is `:379-447`; it frames SSE lines at `:410-417`, calls the same parser at `:418`, then currently applies `event.cursor > lastCursor` before dispatch (`:419-426`). Both paths therefore have a common strict parser seam and distinct cursor gates. Per the accepted decision, the observation must be strictly validated and diverted before either cursor gate; it must neither compare nor update `lastCursor`.
- `parseStreamEvent` (`:530-549`) parses JSON and checks record/payload shape and an optional matching `payload.case_id`, but accepts arbitrary string event names (`:538-545`), accepts any nonempty cursor string (`:539-540`), and casts the payload/type. It also supplies a current-time fallback for missing timestamp (`:546`). Keep ordinary event behavior scoped; a strict named observation projection needs its own discriminator/guard before the generic cast/fallback.
- The current public `CaseworkPort.subscribeEvents` callback surface is four arguments (`apps/godspeed-cognitive-ui/src/ports/contract.ts:203-216`), and `localAdapter.subscribeEvents` only fans ordinary `StreamEvent`s to listeners (`adapters/local/localAdapter.ts:168-173`). Accepted boundary adds an optional fifth typed observation callback seam in the port and live adapter. The existing `onError` is the transport failure callback; local capacity notices belong on the typed UI-local callback, not `onError`. The app must ignore observations in ordinary `onEvent` and consume typed `onUpdate` once, preserving the original canonical event envelope.

## Reuse candidates for root's design

- Reuse `isRecord` as the first runtime guard, and mirror the test validator's exact-key, safe-integer, finite vocabulary, and conditional-count patterns in a production-scoped observation validator. No installed runtime schema library is already shared by this UI package.
- Preserve the event's source cursor/timestamp and envelope. Resolve the cursor grammar discrepancy before selecting validation: Go transport cursors are `entry_ulid`, while a legacy test regex assumes `epoch.seq`.
- Use strict calendar-aware timestamp validation for the named observation; current TypeScript checks and generic fallback are insufficient. Go's `time.Parse(time.RFC3339Nano, ...)` provides the exact server-side rule but is not directly callable in the browser.
- Keep observation admission ahead of cursor ordering in both branches and add the named kind to the native EventSource listener allowlist. The fetch branch already routes any named event into the shared parser, so it needs the same validated observation branch without durable-cursor advancement.
