## Findings

1. **Signing is feasible but remains a new decision.** `crates/sea-forge-ledger/src/lib.rs:5-6` exposes `signing`; `signing.rs:5,63-80` exports `SigningKey`, `sign_bytes`, and `verify_signature`; `crates/sea-forge-server/Cargo.toml:13` already depends on `getrandom`. A process-lifetime key can avoid persistence and a new dependency. Tokens must be signed only after the server validates the prefix. However, the proposal does not cap encoded-token size/field lengths before parsing or base64 decoding; `verify_signature` decodes the supplied signature (`signing.rs:68-80`). Add a strict token-size and fixed-field bound before allocation/decoding. Process restart invalidates old tokens; that stale-token path must remain consistent with `REQ-C2-FRONTIER-002`, which assigns unknown impact and cell-wide unavailability/draining to invalid continuation or head binding. The options document correctly labels signer/key lifecycle as requiring separate approval.

2. **The proposed 1 MiB raw-row cap conflicts with the supported event size.** C2 allows 1,048,576 serialized response bytes per page (`limits.event_page`, spec lines 96-104), and the candidate permits a 1 MiB individual event. A ledger row adds the serialized `LedgerEntry` envelope around `payload`: fields include IDs, ordinal, record kind, reference vectors, hashes, timestamps, and writer identity (`crates/sea-forge-ledger/src/types.rs:191-216`); `append_under_lock` constructs that envelope (`types.rs:1005-1075`). Therefore a maximum-sized payload cannot fit in a 1 MiB raw row. Recommend **2 MiB per raw row and 4 MiB aggregate input per page** as a conservative candidate, separate from the output cap. This is a proposed admission limit, not a proven maximum: variable envelope fields have no general size limits in `LedgerEntry`. Bound/validate those metadata fields or explicitly allow typed-unavailable for rows exceeding the cap. These input limits are not in the current C2 `event_page` values and require explicit policy approval.

3. **Empty-ledger and scan-start behavior are unspecified.** `read_last_entry` returns `None` when the file is absent or empty (`types.rs:765-782`); the first actual append is ordinal 0 (`types.rs:1029-1030`). No real pinned head cursor/ordinal exists in that case, while `REQ-C2-RANGE-001` requires a real pinned head pair. Define an empty-ledger result without a synthetic cursor/head, or fail closed. Also state explicitly that v2 scans from actual origin or a verified continuation; `from_cursor` may filter returned frames but cannot act as proof that the preceding prefix was validated (`REQ-C2-RANGE-003`).

4. **The 1 MiB output cap and 1 MiB event cap are not jointly transportable at their limits.** `EventFrame` contains cursor, kind, optional case/run IDs, detail, and commit timestamp (`crates/sea-forge-server/src/sfwp/events.rs:19-31`). A maximal serialized event plus a page envelope exceeds the 1 MiB response limit, even when its event alone is within a 1 MiB event cap. Define a lower transportable event maximum or change the response limit; do not claim every allowed maximal event can be delivered under both limits.

5. **The lock/prefix proposal is compatible only under its stated cooperative-writer boundary.** Existing appends take the per-ledger exclusive lock (`types.rs:690-723,1005+`), and the server has a nonblocking lock example (`crates/sea-forge-server/src/lib.rs:1092-1115`). A bounded 50 ms head snapshot followed by unlocked page scanning is consistent with the spec's 50 ms lock-wait limit if supported writers append under that same lock and do not rewrite prior bytes. The C2 external-writer rule explicitly leaves manual, plugin, and out-of-tree writers unsupported (`REQ-C2-EXTERNAL-001`, spec lines 331-337); the reader cannot claim it detects arbitrary mutation of already-scanned bytes. The design should say exactly which raw bytes (including row delimiter) its checksum covers and make offset/end arithmetic checked.

6. **Compatibility recommendations are aligned, but still unimplemented.** Preserve the legacy `{events: [...]}` response and existing request fields/defaults; add only the approved optional `range_version`, branch v2 to separate response/frame DTOs, and keep old `EventFrame` used by subscriptions unchanged. Current `EventsGetRange` has only `from_cursor`, `to_cursor`, and `limit` (`crates/sea-forge-server/src/lib.rs:748-790`); current `get_range` fully materializes `read_entries()` (`events.rs:169-208`; `types.rs:785-802`). The proposed bounded reader and v2 DTOs are therefore new work. The method-local unknown-cursor/unavailable error split is consistent with the existing unknown-cursor behavior and C2 fail-closed rules.

## Material differences from the current normative/source baseline

The proposal adds authenticated continuations, process-lifetime key state, bounded raw-row/page-input limits, a 50 ms head-snapshot reader, and a v2 page response. Continuation binding and v2 paging are required by C2; signer lifecycle and raw-byte limits are design choices not specified in the existing numeric page limits. Existing source has no bounded reader, continuation signer, `range_version`, or v2 DTO. The proposal preserves the legacy response and `EventFrame`, which matches the compatibility boundary. It must not be treated as source approval, exact-hash operator approval, runtime proof, or migration readiness.
