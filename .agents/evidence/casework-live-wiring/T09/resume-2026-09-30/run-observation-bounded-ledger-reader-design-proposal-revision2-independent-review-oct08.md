## Findings

Revision 2 resolves the previous HOLD findings with concrete rules: the process-lifetime signer binds stream, pin, predecessor, offsets/checksum, and exact range-filter digests; validates a bounded 4,096-byte token and 2,048-byte payload before decoding/using seek fields; issues tokens only after validated prefix; treats failed trusted-owner continuations as no-ack and global unavailable/rebuild; defines absent/empty-stream `pinned_head: null` without a synthetic cursor; scans from actual origin or a verified continuation while `from_cursor`/`to_cursor` only filter emitted frames; pins under a 50 ms lock and scans unlocked under the supported append-only prefix assumption; and selects 2 MiB raw rows/4 MiB page input, with exact whole-response byte measurement and no skipped undelivered event. It expressly keeps the 500 ms/two-page Go scheduling bound separate from reader elapsed time. These choices match the cited root clarifications and C2 `REQ-C2-RANGE-001..003`, `REQ-C2-FRONTIER-001..002`, and `limits.event_page` (spec lines 90-104, 203-252). It retains the legacy `{events: [...]}` wrapper and `EventFrame`, separates v2 DTOs, and keeps errors local to SFWP.

**Remaining blocker — strict unknown-field rejection is not accounted for.** Revision 2 requires rejecting unknown top-level `LedgerEntry` fields and unknown fields in `StoredEvent` (proposal sections “Bounded input…” and “For `record_kind == sfwp_event`…”). The current types do not declare `#[serde(deny_unknown_fields)]`: `LedgerEntry` is the derived type at `crates/sea-forge-ledger/src/types.rs:191-216`; `StoredEvent` is at `crates/sea-forge-server/src/sfwp/events.rs:47-59`. Current `read_entries()` deserializes via ordinary `serde_json::from_str` (`types.rs:785-802`), and current `frame_from_entry` permissively defaults missing `kind`/`detail` (`events.rs:92-107`). Thus strict unknown-field rejection changes acceptance behavior; because the proposal reuses one strict scanner for legacy and v2, the change affects existing no-version calls too. The C2 spec requires malformed-row/payload refusal and preserves the legacy response shape, but does not expressly define unknown fields as malformed or require rejection. Revision 2's pending-decision list names signer lifecycle, token/input budgets, empty-head wire arm, and cursor/filter decisions, but omits this compatibility policy. Add it as an explicit normative/operator decision (including its legacy-path effect), or narrow the proposal to a source-compatible field policy. Until then, the proposed behavior is underspecified relative to the current contract.

## Material differences and remaining boundary

The proposal's process-only signer, token encoding/caps, raw-row/page input caps, verified-empty wire arm, and deferred v2 unknown-cursor behavior are all identified as proposals pending separate operator approval and spec/ADR updates. Strict unknown-field rejection is an additional, unlisted behavior choice. No dependency, kernel verb, authority rule, synthetic cursor, or new history is introduced.
