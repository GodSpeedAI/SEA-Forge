## Findings

Revision 4 repairs revision 3's blocking hash-semantic mismatch. It directs parsing through the existing typed `LedgerEntry`, calls `payload_hash(&entry.payload)` and `entry_hash(&entry)`, and withdraws raw-row hashing and fallback semantics. This matches the implementation: `payload_hash` canonicalizes the full `Value` (`crates/sea-forge-ledger/src/types.rs:46–49`); `entry_hash` serializes the typed row, removes `entry_hash`, canonicalizes, and applies the existing domain (`types.rs:53–61`). `LedgerEntry` has no `deny_unknown_fields` (`types.rs:191–216`) and `read_entries` deserializes with ordinary Serde (`types.rs:785–802`). The append and verifier paths call the same helpers (`types.rs:1056–1058, 1125–1132`). Therefore unknown top-level row fields remain tolerated and are not included after typed deserialization, while unknown fields retained in `payload` remain in both relevant hash inputs. This resolves the prior HOLD without changing the established hash protocol.

The revision 4 continuation refinement also satisfies the resolved-filter addendum. The signed token carries nullable canonical-decimal `resolved_from_ordinal` and `resolved_to_ordinal` alongside the exact presence/length/UTF-8 filter bindings. A present but undiscovered filter remains null, distinguishable from an absent filter through the signed binding. The proposal only records a resolution when the exact cursor row is inside the acknowledged validated prefix; an undelivered lookahead row advances neither the resolved state nor the scanned-through frontier. Resume validates resolved ordinals against that authenticated prefix, discovers outstanding filters only from newly validated rows, and applies exclusive-from/inclusive-to using those ordinals. Actual ordinal zero is `"0"`, not a sentinel. Origin cannot carry resolved bounds. At a verified-empty stream a present bound returns the existing unknown-cursor input error; on nonempty history an unresolved bound remains deferred until the actual pinned head, where absence is an input error. These rules preserve the prior no-lookahead-ack boundary and do not add a rescan index, cache, dependency, or limit increase.

The earlier bounded-reader requirements remain present in the base proposal and are not displaced by either overlay: legacy request/response shape and `EventFrame` remain intact; v2 uses distinct DTOs; the process-only signer, bounded token validation, pinned cooperative head, bounded input, full-envelope response cap, whole-row continuations, malformed-event refusal, and local typed errors remain proposals pending the specified operator/spec decisions. The C2 reader still has no added per-page elapsed deadline; the separate Go scheduling bound remains distinct. The full origin-to-head validation and trusted-owner no-ack/global-unavailable recovery rules remain consistent with the spec.

## Material differences and disposition

Revision 4 adds two substantive corrections to revision 3: it restores the current typed entry-hash protocol while preserving payload hashing over the complete `Value`; and it adds signed resolved filter ordinals so page continuations do not need to rescan an unbounded prefix to rediscover cursor bounds. The latter is a material addition from the original review grant, explicitly supplied by the root addendum and kept inside the existing token, page, and endpoint design. Revision 3's exact-byte stream binding, unknown-field tolerance, event-field validation, and correction to the Rust unseen-ID claim remain. All previous proposal-level findings are closed on the reviewed text.
