## What actually ran

Both assigned Go commands were executed through `functions.exec`, calling the
nested `tools.exec_command` directly with the recorded command strings and
package workdir. The manager invocation returned a running session; it was
polled to completion using `tools.write_stdin` through `functions.exec`. The
retained-helper invocation returned completed in its initial `exec_command`
call. The tool results exposed output text and numeric exit code 1 for each.
Both tool outputs showed the selected tests failing at the described stub
assertions, and no compile/setup error appeared in those returned results.

The two preflight summaries were generated by direct `exec_command` calls to
Python that read `/proc/meminfo`, hash the four source/test files, and printed
the time, resource values, identities, and intended command. Those returned
text summaries were manually transcribed into the evidence directory with
`tools.apply_patch`.

After each Go invocation completed, its returned output text was manually
transcribed into the corresponding `*-output-oct07.raw` artifact with
`tools.apply_patch`; the returned integer exit code was manually written as
`1` in the corresponding `*-exit-oct07.raw` file. The six evidence files were
not written by redirecting process stdout/stderr or exit status to `/tmp`.
No original preflight/output/exit capture files were saved in `/tmp` or another
known location. Read-only searches for these specific filenames in accessible
`/tmp` paths and the evidence directory found only the six evidence artifacts
listed below. Therefore, the archive hashes below hash the manually written
artifacts only; they are not hashes compared with original process-output
files. Byte-for-byte identity to the original tool responses is not
established.
