## Findings

The root decisions resolve the recon’s three open integration questions consistently with revision 6 and its corrections.

* **List outcome is explicit.** The root decision adds a lease list-state value from the existing contract enum, set from the validated `Prepare` result under the manager mutex. The enum is exactly `complete` / `unavailable` (`apps/godspeed-casework-go/internal/contract/contract.go:188,440`); `observation_state=no_runs` remains a separate successful-empty result (`contract.go:228-238,442`). Current `prepare` returns an unavailable DTO plus a nonnil completed lease when `run.list` errors (`apps/godspeed-casework-go/internal/server/run_observation_manager.go:394-411`), while a successful empty list also yields a lease and zero pollers (`run-observation-manager-concrete-proposal-revision6-oct06.md:90-98,451-456`; recon’s empty-list test citation). Thus using the saved list result, rather than `len(lease.pollers)`, is necessary and sufficient to distinguish them. There is no existing `Next` method or implementation symbol for `ErrRunListUnavailable`; that error is a revision 6 contract obligation and should be implemented as such, not described as an already-present source API.

* **Next owns its context and admission.** `prepare` creates and cancels its local derived context and closes `creatorDone` before returning (`apps/godspeed-casework-go/internal/server/run_observation_manager.go:350-371,569-570`). It cannot safely be reused for a later Next call. The root decision’s separate caller context plus outside-lock authorization/guard and under-lock exact lease/token/entry/forward-and-reverse-ref checks preserve revision 6’s no-callback-under-lock rule. The current lease has only manager, forward refs, caller/as-of cursor, and drain channels (`manager.go:81-90`); it has no list result, watermark, wake, single-Next guard, operation WG, or notifier WG. Those are future private integration state, not current behavior.

* **Retention disposition matches correction 2.** Root requires `retainedRetentionUnavailable` to return a typed zero aggregate, keep the same attachment/slot, leave the watermark unchanged, and recover only on a later complete candidate fitting with the full identity ledger. Correction 2 requires exactly that, while forbidding the prior retained value from being presented as current (`run-observation-manager-revision6-retention-initializer-correction-revision2-oct06.md:14-35,43-49`). The worker continues after a nonterminal over-cap marker (`apps/godspeed-casework-go/internal/server/run_observation_poller_worker.go:338-357`); candidate construction permits recovery from that marker while rejecting only terminal-retention-failure and stop-scheduling predecessors (`run_observation_retained_version.go:51-76`). This extends the same policy coherently to Next without misclassifying it as transient read failure.

* **Capture, commit, and wake ownership are coherent.** Revision 6/addendum require one atomic captured version, copied ledger, and prior watermark; ordinals above captured H are excluded, and no recapture/retry occurs (`run-observation-manager-concrete-proposal-revision6-oct06.md:392-423`; `run-observation-manager-concrete-proposal-revision6-addendum-oct06.md:14-30`). The pure assembler accepts precisely state + copied ledger + prior scalar watermark and ignores copied ledger entries above H (`apps/godspeed-casework-go/internal/server/run_observation_delta.go:48-80,144-167`). Root’s exact-reference/token recheck, per-lease watermark commit, and coalesced wake when publication advances during assembly preserve those boundaries. A capacity-one never-closed wake, notifier `Add` under the same mutex before unlock, sends/`Done` outside, and drain waits outside avoid send/close races and Add/Wait races (`run-observation-next-integration-root-decisions-oct08.md`, “Captures, wake ownership and commit”). This is not yet wired: current worker publishes `entry.current` under the lock and has no notification target registration (`poller_worker.go:367-429`).

* **Terminal outcomes and teardown are consistent.** A fitting accepted terminal `retainedCurrent` remains readable after its worker closes `workerDone`; terminal retention-failure / stop markers are not disclosed and must stop future reads before JOIN. Correction 3 requires a distinct safe internal stop decision before waiting, worker-owned `workerDone`, and capacity held until worker/operations/notifiers actually join (`run-observation-manager-revision6-retention-initializer-correction-revision3-oct06.md:14-44`). Current worker already rejects new claims for terminal current execution or terminal/stop markers (`apps/godspeed-casework-go/internal/server/run_observation_poller_worker.go:25-46`) and drains terminal marker leases only after unlocking (`:401-429`). Next must schedule the existing asynchronous drain and return through its deferred operation release; waiting synchronously while holding its own operation would contradict correction 3’s join requirements. The root decision rules that out. Existing `finishLeaseDrain` currently joins creator and workers before removing cohort capacity (`apps/godspeed-casework-go/internal/server/run_observation_manager.go:785-813`); integrating operations/notifiers into that owner is a required future change, not a present guarantee.

## Verdict and boundary

**No semantic contradiction found in the bounded root decisions.** The source/API wording caveat above is the only correction: `ErrRunListUnavailable` is normative in revision 6 but not currently implemented. The decisions add no public schema, SSE, dependency, authority rule, or new retention cap. Revision 6 and correction 3 still label the 16-cohort/128-attachment policy and 1 MiB image/overflow behavior as requiring exact operator approval (`revision6:588-595`; `correction3:53-75`); nothing here treats the user’s six public C2 recommendations as approval of those private limits. This review grants no source release, private-cap approval, gate result, or runtime claim.
