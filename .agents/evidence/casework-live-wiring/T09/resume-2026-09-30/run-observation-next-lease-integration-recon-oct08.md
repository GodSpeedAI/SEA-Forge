## Shortest coherent integration shape

Keep `run_observation_delta.go` and its pure tests frozen. Add one manager-owned `Next(ctx)` entrypoint returning a private aggregate of `runObservationRunDelta` and gaps, implemented in a small new `run_observation_next.go` (or, if root requires the fewest files, in `run_observation_manager.go`). Extend the lease only with the exact private controls revision 6 requires: per-key scalar watermarks, one capacity-one `wake` channel that is never closed, a `nextInFlight` guard, plus per-lease `operations` and per-target notifier `notifyWG` ownership. Initialize a watermark from captured H in the same critical section that validates each retained current pointer and before initial DTO hydration. A valid empty-list lease has a nonnil empty delta; a refused-list lease has the distinct typed `ErrRunListUnavailable` behavior specified by revision 6.

`Next` first admits exactly one operation per live lease under `m.mu`: check manager/cohort/lease/forward-and-reverse ref identity, reject a competing call, set `nextInFlight`, and `operations.Add(1)`. Drain changes the same lease to draining under the same mutex before waiting outside, which prevents any later Add from racing `Wait`. Wait outside the lock on the caller context, `leaseDone`, and the capacity-one wake (manager Stop signals `leaseDone` to each lease before waiting). On wake, capture for every key the exact manager/lease/poller pointer, immutable current state pointer, prior watermark, and copied exact `SeenByID` map under `m.mu`; release the lock before auth/guard, delta assembly, cancellation, or channel notification. Sort run keys by exact RunID bytes for aggregate output while each delta retains source frame order.

If any captured state is unavailable/malformed or any run assembly/auth/guard step fails, discard the entire candidate aggregate and all candidate watermarks. `ErrPollerReadUnavailable` is transient: zero delta/no watermark advance, keep this lease attached; the worker already publishes a recoverable `retainedReadUnavailable` marker, continues its cadence, and can publish a later accepted state. A successful terminal `retainedCurrent` version remains deliverable even though its worker is finished; it must not be rejected just because `workerDone` is closed. Terminal retention-failure/stop markers instead fail closed and follow correction 3's stop, notification, actual worker JOIN and detach ownership. Before committing, recheck auth and the same cursor outside lock, then under lock require the exact lease still active, the same `nextInFlight` token and each captured entry still the exact manager entry and both forward/reverse lease ref. Commit only this lease's candidate watermarks. Do not require current pointer equality to the captured version: if it advanced during assembly, retain/ensure a coalesced wake for the next `Next`; never recapture or retry this call.

On each `finishPollerRead` publication, while `m.mu` still protects the `entry.current` pointer transition, collect every currently eligible exact lease target and call that target's `notifyWG.Add(1)`. After unlocking, do nonblocking sends to each never-closed `wake`, with exactly one `Done` per target even when a send coalesces. Drain marks the lease ineligible before waiting on `notifyWG` and `operations`; both Wait calls and all sends remain outside `m.mu`. A terminal `Next` auth/context/stop failure can start existing asynchronous `startLeaseDrain` and return its zero result; its deferred operation Done lets the drain owner finish, avoiding self-join. No worker or waiter closes `wake`.

For a future bounded implementation/test change, the minimal production partition is `run_observation_manager.go` for lease fields and initial watermark handoff; `run_observation_poller_worker.go` for publish notifications; and a small `run_observation_next.go` for the Next operation. Add a new `run_observation_manager_next_test.go` using existing channel-controlled list/trace/auth/guard fakes. Preserve the existing lifecycle and delta tests. Required Next cases: successful empty versus failed-list distinction; initial watermark before hydration pruning; independent per-lease watermarks over one shared poller; read-failure zero/no advance with retained attachments followed by worker recovery/wake; one-Next concurrency rejection; poll publication during assembly preserves a second wake; context/session/cursor/Stop/detach wake and drain; successful terminal final value; and no callback/send/cancel/wait under `m.mu`.

## Concrete blockers and decisions for root

1. **Completed list outcome is not representable today.** A refused/unavailable list returns a successful empty lease (`manager.go:390-410`) with no pollers; a genuinely successful empty list also returns an empty lease (`run_observation_manager_test.go:296-343`). Revision 6 requires `Next` on the former to return `ErrRunListUnavailable` and the latter to behave as a valid empty cohort. No current field or map difference distinguishes them. Root must authorize one private outcome marker (e.g. a lease list-result enum/boolean) or choose a contract-compatible existing representation before coding; do not infer failure from zero refs.
2. **Nonterminal retention-unavailable disposition remains proposal-sensitive.** Read failures have an explicit transient recovery rule; terminal retention failure has stop-before-join correction 3. Revision 6 addendum says retention overflow's terminal-versus-recoverable disposition must be explicitly decided and not inferred. Existing worker continues after a nonterminal `retainedRetentionUnavailable` marker (`poller_worker.go:338-357`) and may recover. Root should explicitly confirm Next's error/attachment behavior for that marker against the still-proposed retention policy; no need to change the pure assembler.
3. **Operation self-drain must remain asynchronous.** If terminal Next invokes a drain and synchronously waits for it before releasing its own registered operation, `finishLeaseDrain` waiting for `operations` deadlocks. The existing asynchronous drain owner supports a zero-result return followed by its own deferred operation release; preserve that order.
