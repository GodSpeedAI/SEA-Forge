## Contract review

**Admission, context and creator ownership.** `beginPrepareOperation` reserves the exact cohort and registers creator work under the same mutex (`run_observation_manager.go:112-129`), so Stop cannot race a late WaitGroup add. `prepare` derives a local context and bridge, and each exit cancels that local context, joins the bridge, and completes the exact creator registration before any owned rollback wait (`:321-381`). The list callback is followed by a cancellation/current-guard recheck; reservation checks the receive-only prepare channel, exact cohort identity, stop state and lease eligibility under the mutex (`:383-461`, `:141-236`). All entries in the immutable owned batch launch before readiness waits (`:456-489`, `run_observation_poller_worker.go:9-15`). Request cancellation applies to that Prepare's list and initial wait; shared workers use their independent manager-owned context, matching revision 6. A surviving eligible lease can keep shared work alive after one creator fails.

**Read accounting and A outcomes.** Selected rows are validated against the guarded parent set and deduplicated before reservation; selection is not backfilled after a bad or over-cap row (`manager.go:416-458`). The returned read count is derived from completed owned initializer results, not reservations (`:491-500`). Real initial unavailable/invalid/unretainable reads remain successful A with owner count one and shared count zero; the over-size nil-current key path produces no poller entry and no read while returning a successful A lease (failure fixture `:654-684`). Stop/cancel before first read uses the existing invalid initializer code with stopping/draining phase, no current and one readiness close; Prepare fails with typed unavailable, zero DTO and nil lease (`worker.go:244-268`; failure fixture `:180-229`). Actual list unreadable counts rely on the production adapter's distinct-ID contract as the original assignment specifies.

**Authorization and read claims.** A claim requires manager admission, exact `m.pollers[key]` entry, valid phase/current state, and at least one non-draining lease whose forward map points to that exact entry (`worker.go:19-47`; `manager.go:277-284`). Before each actual read the worker snapshots eligible refs under the mutex, performs each authorization and case/cursor/parent guard check outside it, rechecks the entry/prior pointer/phase and forward membership, and retries to validate any newcomer before proceeding (`worker.go:71-107, 151-242`). The worker context is checked outside the lock immediately after the final membership check and before `ReadRunTrace` (`:101-108`). A claim that linearizes before Stop remains owned through actual return/JOIN, consistent with the approved read-start contract.

**Publication, cap and terminal state.** Complete candidates pass the unchanged retained-image and combined outer-image encoder before pointer publication. The worker reauthorizes watchers and guard state, then rechecks entry identity, previous pointer, phase and eligible membership before atomically replacing current (`worker.go:270-429`). The terminal fallback decision is computed from the final phase/state after outer-cap fallback (`:338-365`), preventing the stale-terminal decision found in the rejected source. A fitting terminal publishes the accepted current, leaves valid leases eligible for final/cache DTOs, and returns without another read; claims reject terminal current (`:19-47, 291-296, 401-429`; authority fixture `:274-354`). An unretainable terminal keeps the prior immutable ledger under its fixed marker, signals exact eligible lease drains outside the lock, and remains capacity-owned until actual worker JOIN (worker `:345-365, 401-429`; fixture `:403-505`).

**Invalid watcher and survivor.** Watcher authorization drains only invalid leases; shared work continues when another lease remains eligible. The authorization loop validates a newly admitted exact forward member before treating the watcher set as complete (`worker.go:161-223`). The fixture covers invalidation both during a held read and before the port call while a valid survivor attaches during the held authorization check; it asserts invalid cohort/ref/forward cleanup, survivor membership and exact current key, and only the single authorized shared read (`authority_terminal_test.go:620-804`). Revocation/cursor changes before and during reads prevent disclosure/publication (`:509-619`). Final empty-list and unavailable-list handoff cases reauthorize current context and require zero reads and full cleanup on refusal (`:807-863`).

**Drain, timeout and Stop.** The approved clarified interpretation is applied: `lease.pollers` is eligibility; `entry.refs[lease]` may persist as non-eligible drain ownership until the real worker JOIN. `takeLeaseDrainLocked` atomically claims `draining`, clears forward membership, removes reverse refs immediately only when an eligible survivor remains, and otherwise retains them in the owned drain work (`manager.go:719-756`). `startLeaseDrain` has one first-transition owner; it closes `leaseDone`, cancels watcherless workers and starts the drain after unlocking (`:759-776`). The drain waits on exact `creatorDone` and worker completion, then removes reverse refs/capacity under exact identity checks and closes stable `drainDone` outside the mutex (`:785-814`). Caller timeout returns an error without releasing the background owner (`:816-825`). Stop closes admission and snapshots work under the mutex, signals/cancels outside it, then waits for creator registrations, lease drain completion and actual workers (`:828-908`). Detach waits only its lease's drain (`:910-915`). This preserves the creator-before-own-drain rule and prevents unrelated held list creators from blocking detach.
