## Blocking findings

1. **Newest-1024 retention keeps all selected frames alive.** `run_trace.go:50-53` allocates `selected` with capacity `len(rows)`, `:94` appends every selected frame, and `:99` returns `selected[total-runTraceRetention:]`. This is a subslice of the original backing array, which remains reachable through `RunTraceSnapshot.Frames` at `:101-105`. The snapshot’s length and capacity are 1024, but its backing allocation still contains the discarded prefix frames and their event-ID/timestamp references. A caller holding snapshots across concurrent pollers therefore retains memory proportional to the entire returned trace per snapshot, contrary to V3’s newest-1024 retained result. The fixture checks 1027-row length/order but does not detect retained-prefix backing storage (`run_trace_test.go:416-432`). Copy the retained tail into a fresh 1024-element backing array or use another bounded output representation while keeping full-array duplicate validation and returned-frame counts.

2. **Timestamp parsing accepts non-RFC3339 comma fractions.** `run_trace.go:73-78` uses `time.Parse(time.RFC3339Nano, timestamp)`. The pinned Go 1.27.1 standard-library source shows that `Parse` tries `parseRFC3339` and falls back to generic layout parsing (`src/time/format.go:1026-1033`). The generic `stdFracSecond9` parser accepts both comma and period (`src/time/format.go:1316-1328`, `commaOrPeriod` at `:1525-1527`); `parseStrictRFC3339`’s strict comma check is disabled by `case true` (`src/time/format_rfc3339.go:155-175`). RFC3339 fractional seconds use a period. Thus a timestamp such as `2026-10-05T12:13:14,123Z` is accepted by this validation path although it is not RFC3339. The current malformed timestamp fixture uses only `yesterday` (`run_trace_test.go:389`), so the permissive case is untested. Add strict syntax validation before accepting the parsed time.

## Error and privacy path

Malformed decoder/projection errors are converted to the fixed `runTraceUnavailable()` message (`run_trace.go:31-43,230-232`); raw decoder errors and invalid values are not interpolated. The `Client.Do` error path at `:27-29` returns the zero snapshot and the typed error unchanged, as required to preserve authority classes. I traced this path: `DecodeResponse` copies the wire `error` string into `Refusal.Message` (`frame.go:546-578`), `Refusal.appErr` includes it in the typed error (`frame.go:495-514`), and `Client.Do` returns it (`client.go:395-416`). The in-tree `run.get` handler currently creates `not_found` and `record_unreadable` messages from the requested run ID or a fixed unreadable-record explanation (`crates/sea-forge-server/src/sfwp/run_views.rs:332-350,836-855`; mapped at `lib.rs:2408-2415`); I found no current `run.get` error producer that includes trace payload fields or decoder input. Therefore I found no separate source-backed payload leak in the present authority path, and the existing refusal-class preservation should remain.

## Other V3 contract checks

Source review found the main projection logic aligned with the frozen contract: blank expected IDs are rejected before `Do`; one logical `Client.Do(NewRunGet(runID))` is used; errors return a zero snapshot; response ownership and standings are exact; `trace.jsonl` presence and exact `u64` bytes are checked; unknown string kinds are omitted before validating their other fields; selected rows validate IDs/timestamps and duplicates across the full returned array; command metadata accepts only the allowed optional forms and exact safe integer range; source order and timestamp text are preserved; counts are computed before retention; unknown payload fields are not copied. Empty successful frames remain nil under the approved erratum. I found no byte/row consistency inference or source-completeness claim in this adapter.

The two blocking issues require a new bounded production repair and a fresh independent source review before the compiler token is used for focused tests. No source, fixture, port declaration, or other project file was changed in this review.
