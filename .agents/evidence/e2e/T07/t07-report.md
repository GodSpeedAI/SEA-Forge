## What was built

Smallest delta honoring the frozen contract, following the T03–T06 native-gate
precedent: one canonical emitter module in SWE_SEED plus one native ingestion
gate module in sxr-core over the same v1 wire family. No new envelope family.
No cross-repo dependency in either direction: sxr takes NO dependency on
SWE_SEED (the frozen producer vocabulary, identity rules, placeholder
constants, and canonicalization are mirrored from the preregistration), and
SWE_SEED still does not depend on sxr. Parity is enforced through a cross-repo
golden fixture generated by the REAL SWE_SEED emitter and consumed by the REAL
sxr gate (T04/T06 pattern with direction reversed). The spec-0011-era legacy
`emit.rs::emit_proof_completed` is untouched; the canonical surface is built
alongside it.

### Emitter side — SWE_SEED (`crates/swe-seed-core`)

New module `src/federation/proof_completed.rs` (+ `mod.rs` wiring), pure and
transport-free:

- **`emit_proof_completed_verified(settlement, facts, additional_parents,
  completion, identity)`** — emits the frozen E7 payload ONLY against a REAL
  adjudicated settlement: the caller supplies the actual OperationalSettlement
  envelope PLUS the `OperationalSettlementFacts` returned by the real T06
  `OperationalSettlementAdjudicator::adjudicate` for that envelope. Binding
  chain checked before anything exists: (1) settlement passes the composed T01
  boundary gate under OUR model identity (exclusive `sea_forge` producer,
  non-placeholder identity, no drift); (2) facts name THIS envelope's event id
  (forged pairing refused); (3) correlation equality across facts ↔ settlement
  ↔ originating work request (ENV-I3); (4) every projected field validated
  (T04 debt D1 not repeated) including governed `proof_status` vocabulary
  (`passed|failed`) and typed-or-refused optionals; (5) derivation via
  `derive_event` records mandatory causality (`caused_by:` the settlement
  event id always, validated upstream parents additionally — ENV-I4) and pins
  the correlation through the substrate's own mismatch refusal.
- **All 7 frozen required fields present AND validated**: work_request_id,
  proof_result_id, proof_contract (criterion/command/proof_type),
  proof_status, expected_outcome, operational_settlement_ref,
  domain_model_ref (`{namespace, model_hash}` bound to the declared identity).
- **`operational_settlement_ref` is CONTENT-ADDRESSED** (ENV-I7 preferred
  form): `sha256:<hex>` over the canonical JSON of the referenced settlement
  envelope's exact bytes — a reference to immutable bytes, not a path.
  `operational_settlement_ref(&Envelope)` recomputes it deterministically.
- **`expected_outcome` carried verbatim**: the declared expectation projects
  byte-exactly (test-pinned), so the later expected-versus-observed comparison
  binds to what was actually declared, not a downstream rewrite.
- Refusals are typed (`EmissionError`) and happen pre-emission.

### Ingestion side — sxr (`sxr-core`, RealityTrace)

New module `src/proof_ingest.rs` (+ `lib.rs` wiring). PURE per AC-CORE-001
(no I/O); ingestion state is threaded explicitly as a serializable
`IngestState`, so duplicate/claim recognition is restart-survivable when a
caller persists it (proven by a serde round-trip test without FS access).
Gate order, fail-closed before any admission:

1. structural v1 wire shape + well-formed event ids (UUID or ULID-shape);
2. exclusive producer authority: only `swe_seed` may deliver ProofCompleted
   (`ProducerForge` otherwise, both directions tested);
3. identity: structural digest, placeholder refusal (the pinned standalone
   fallback constant `dc144cbd71a483431301ca1bf32e95c014af4edba8dbcc525f505310e30a107e`
   and the all-zero digest), drift against locally-resolved model (ENV-I1/I2);
4. namespace/schema tampering: payload namespace, `domain_model_ref.namespace`,
   `schema_version`, and `domain_model_ref.model_hash` vs declared identity;
5. required-fields battery reporting ALL seven together (T04 D1);
6. typed validation of every projected field incl. optional arrays/refs;
7. mandatory operational-settlement causal parent: the LOCALLY-KNOWN
   settlement event id must appear among recorded `caused_by:` parents
   (`CausalityMissing` otherwise), malformed parent ids refused (ENV-I4);
8. correlation cross-check against the tracked cycle (ENV-I3);
9. duplicate/replay recognition BEFORE consequence under stable identity:
   event id, whole-envelope content digest, and producer idempotency key;
10. content resolution of the cited reference when the settlement bundle is
    delivered: recomputed canonical digest must equal
    `operational_settlement_ref`, the delivered envelope must be `sea_forge`'s
    own settlement carrying the known event id and the same cycle correlation
    (`SettlementBindingMismatch` otherwise — forged parent references cannot
    resolve);
11. claim stability across re-submission: a FRESH envelope re-claiming an
    already-ingested `(work_request_id, proof_result_id)` cycle with divergent
    expected_outcome / proof_status / proof_contract / settlement ref / model
    hash is refused with `ClaimMismatch` NAMING every diverged field — the
    first claim stands and upstream observation history is never silently
    replaced (ENV-I5; identical redelivery is a consequence-free duplicate).
12. admission returns `ComparisonInputs`: the expected-versus-observed inputs
    preserved BY REFERENCE — verbatim `expected_outcome`, verbatim
    `observed_effects` projected FROM THE REFERENCED SETTLEMENT (not an
    editable copy minted at ingestion), each accompanied by content digests
    (`proof_envelope_sha256`, `referenced_settlement_sha256`) so downstream
    comparison can verify immutability rather than trust copies. Nothing on
    this surface creates EvidenceRecorded or any developmental truth; proof
    conformance establishes conformance only (ENV-I8).

## Honest scope notes

- **T07 does NOT prove** RealityTrace produces acceptable developmental
  evidence, nor that GSA settles it — E8/I8/I10 are T08 scope. The sxr gate
  deliberately has no path to EvidenceRecorded; it only preserves comparison
  inputs and refuses rewrites.
- **Reference-resolution boundary characterized honestly**: when the
  settlement bundle is NOT delivered alongside the proof, the gate still
  enforces causality (locally-known settlement id among parents),
  correlation, identity, duplicates, and claim stability — but it cannot
  verify the cited CONTENT digest against actual settlement bytes. That
  limitation is surfaced explicitly on `ComparisonInputs`
  (`referenced_settlement_sha256 == None`, `observed_effects == None`) rather
  than papered over (sxr test
  `t07_without_the_delivered_settlement_...`). When the bundle IS delivered,
  resolution is strict and fails closed.
- **Normalization-vs-source-facts characterization**: the gate performs NO
  normalization of upstream values — `expected_outcome` and (when delivered)
  `observed_effects` are stored verbatim next to their content digests, so any
  later mutation is detectable by digest comparison. The one intentional
  equivalence class is canonical JSON (sorted keys, compact separators), used
  identically by emitter and ingester for digests; array ORDER inside payloads
  is preserved (not canonicalized away), so effect ordering differences would
  be visible as different digests rather than silently equated.
- **Path-only refs**: `artifact_refs`/`trace_root`/`output_ref`/
  `proof_evidence_refs` accept scheme-shaped refs; only `sha256:`-prefixed
  refs get strict digest validation. The settlement reference itself is always
  content-addressed. Non-content-addressed optional refs remain a residual
  ENV-I7 gap, accepted here because the v1 substrate offers no content store
  for them; flagged rather than silently blessed.
- The E4 GovernedWorkRequest causal parent used in tests is a stand-in built
  through the real canonical builder (`make_event`) with the correct
  authoritative producer stamp; the MANDATORY parent in every emission is
  always the real adjudicated settlement.
- Durable persistence of `IngestState` is the caller's concern (sxr-core is
  no-I/O by AC-CORE-001); restart survival is proven at the serialization
  level, not wired into the sxr CLI — production wiring remains future scope.
