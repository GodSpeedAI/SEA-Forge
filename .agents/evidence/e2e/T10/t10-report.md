## Honest scope notes

- **T10 does NOT prove whole-cycle causal continuity — T11 scope.** One DevelopmentalMemory can be derived and measurably biases the next navigation ranking, but the report does NOT demonstrate a single `work_request_id` traversing the full frozen loop `E0→E10` with stable `domain_model_ref` and causal-parent survival, nor replay/restart provenance across every component. That is the explicit `does_not_prove` of T10 (`T11: Settle Whole-Loop Causality, Replay, and Recovery`).
- **Durability boundary:** "durable" here is the local `LedgerStore` flock-guarded JSONL seam (same substrate T09 uses) with restart survival via `load_developmental_memory_state` replay-through-the-gate. It does NOT exercise an external Postgres/NATS ledger restart; the deployed NATS→ledger bridge live composition is untested (offline-first harness, no broker). The exported CK file is filesystem-bridged; live `CK_LEARNING_PROPOSALS_LEDGER` env wiring to a package vs dev store is configuration, not proven here.
- **Capability_state honesty is structural, not semantic relevance:** `build_developmental_memory_from_store` recomputes lifecycle via `infer_capability_lifecycle`/`compute_metabolization` honestly (one success never yields `metabolized`), but it cannot verify that the `variation_context` values were *relevant* variations for the capability — that would require a declared variation vocabulary, which does not exist.
- **Memory is evidence, not authority — by design:** `apply_developmental_memory_to_candidates` only boosts horizon/direction scores; it never writes `governance_allowed`, `settlement_accessible`, or `payment_capacity`. Tests prove `governance_blocked`, `payment_capacity_exceeded`, `settlement_inaccessible` stay blocked. A caller that inverts the documented order (gate → memory instead of memory → gate) would violate I12; the code comments and tests name the correct order but cannot statically forbid a future caller from reordering.
- **CK provenance is filename + ledger-line level:** the export preserves the full developmental envelope (including `provenance.chain` and `domain_model_hash`) per line, so `learning-proposals://<id>` remains citable with source ref. The CK resolver now handles both raw and `LedgerStore`-wrapped envelopes and backfills `proposal` from `domain_area/status` when needed; it does not cryptographically pin the upstream settlement hash of each proposal — the envelope's own `caused_by` chain does (checked in export, not re-verified by CK's citation fetcher).
- **Pre-existing failures were neither fixed nor extended:** the 5 documented env failures + `psycopg` e2e collection error reproduce identically before and after.
- **No status projection was marked:** as builder, this report does not update `.agents/status/e2e-current-status.yml`; independent adversarial CONFIRM remains a separate role (T09's `independent_adversarial` pattern).
