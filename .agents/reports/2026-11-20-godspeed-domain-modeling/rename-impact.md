## Contract and persistence limits

- Refer to current public fields and identifiers verbatim in interoperability documentation. A canonical prose rename gives no permission to silently rename CEP `scope.world_ref`, the evolved E-series events, `assignment.v1`, or a capability ID used by another client. Any externally visible revision needs an explicit producer/consumer inventory, version and conformance decision. Change schema sources and regenerate outputs through their owning tools.
- Detect each persisted event version from its producer, kind, issuer and source references. A missing discriminator alone cannot classify arbitrary historical events. Apply PR #107’s local default only where the originating local event family proves that meaning. Preserve the previous record, signature, digest, ledger ordinal and immutable receipt ID. Use a new record or rebuilt projection for corrected interpretation.
- Remove misleading internal aliases once references are migrated. Source consumers, command and event vocabulary, persisted projections, generated bindings, fixtures, run IDs and UI labels can have different release and integrity owners. Prefer a single supported internal name after cutover.
- The high-cost changes are identity pinning, accepted .sea or frozen spec edits, and public record evolution. Approve those independently of editorial edits. Distinct domain identities do not justify separate stores or additional runtime hierarchies.
