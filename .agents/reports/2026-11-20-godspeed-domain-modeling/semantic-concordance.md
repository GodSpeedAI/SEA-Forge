# Cross-product semantic concordance

“Identical” means the same contract or domain identity, within its scope. A projection preserves selected source distinctions. A specialization adds constraints. A transformation consumes one kind of subject and produces another. Related concepts keep separate identities and authority. “Conflated” identifies existing language or code that supplies the wrong identity or claim.

## World, representation, and case

| Concepts | Relationship | Boundary rule |
| --- | --- | --- |
| Domain → Domain Model → Semantic World → Semantic Projection | Declaration, then resolution, then projection | The domain is the subject matter. A model declares its distinctions. Resolving the source and dependencies supplies the named semantic meaning. A projection exposes selected distinctions in a consumer’s form and preserves provenance. [D1](source-evidence.md#d1-domainforge) |
| DomainForge World Reference and CEP `scope.world_ref` | Identical identifier when corroborated | DomainForge computes the identity from the full model identity tuple. CEP carries it. A syntactically valid reference remains an assertion until its required binding is verified. [D1](source-evidence.md#d1-domainforge) · [P1](source-evidence.md#p1-cep) · [S1](source-evidence.md#s1-sea-forge) |
| Closure Digest and World Reference | Related, distinct. Horizon currently conflates the field names. | Equal resolved meaning can survive a source edit, even when the full revision identity changes. Horizon main derives its `world_ref` from the closure digest, while its misleadingly named `cognate_world_ref` carries the loader’s actual DomainForge reference. The two can refer to the same loaded model at different identity granularities. [H1](source-evidence.md#h1-horizon) · [D1](source-evidence.md#d1-domainforge) |
| Execution World, Execution Manifest, Execution State Digest, Candidate State | Related subjects, representation, identifier, and state | The execution world admits filesystem/process effects. A manifest describes a local state. A digest identifies its content. A candidate is the local state under trial with a parent and adoption status. Multiple lineages can share a digest. No conversion from a digest to a World Reference follows. [C1](source-evidence.md#c1-cognate) · [W1](source-evidence.md#w1-cognate-workbench) |
| Purposeful Case, Case View, Local Change Case, Managed Case | General model, projections, and a governed specialization | The purposeful case is the bounded unit of judgment. Horizon projects work and facts into a Case View. Workbench projects a local candidate workflow into a Local Change Case. SEA-Forge owns the persisted Managed Case and plan. Projection or specialization gives no cross-system ID equality. [T1](source-evidence.md#t1-cognitiveos) · [H1](source-evidence.md#h1-horizon) · [W1](source-evidence.md#w1-cognate-workbench) · [S1](source-evidence.md#s1-sea-forge) |
| Navigation Frame and Read Checkpoint | Related, distinct | The frame is the fixed decision context. The checkpoint is a source read position. A case can persist across many decisions and checkpoints. [H1](source-evidence.md#h1-horizon) |
| Representational Operator and Operator | Distinct | The former transforms a representation. The latter holds standing to make or approve decisions. Neither implies the other. [T1](source-evidence.md#t1-cognitiveos) · [H1](source-evidence.md#h1-horizon) |

## Assignment, identity, and authority

| Concepts | Relationship | Boundary rule |
| --- | --- | --- |
| SEA-Forge-authored `assignment.v1` and Cognate’s wire `Assignment` | Identical contract | Use **Case Assignment** in prose for the delegated case-step attempt, with separate episode, iteration and attempt identity. Cognate validates, binds and folds the contract. Its run is the execution of the assigned attempt. [C1](source-evidence.md#c1-cognate) |
| Case-Step Correlation, Case Assignment, Expert Assignment, Task, Role Invocation | Related, distinct | Horizon’s two-part correlation names a case step. An issued Case Assignment specifies an attempt and can be bound explicitly to a run. Workbench’s Expert Assignment assigns durable Expert work and can survive a failed run and retry. A Task owns separate acceptance. Gauntlet dispatches role invocations against its frozen reference. An Expert Assignment may serve a Task and reference an issued Case Assignment. Preserve both references. [H1](source-evidence.md#h1-horizon) · [C1](source-evidence.md#c1-cognate) · [W1](source-evidence.md#w1-cognate-workbench) · [G1](source-evidence.md#g1-gauntlet) |
| Expert, Agent Procedure, Actor, Principal, Run | Related, distinct | The Expert persists between runs. The procedure is executed. The actor is attributed. The principal is bound to the authority boundary. The run has a lifecycle. Workbench’s Expert-to-principal binding is explicit and its authority depends on admitted work. [W1](source-evidence.md#w1-cognate-workbench) · [C1](source-evidence.md#c1-cognate) · [S1](source-evidence.md#s1-sea-forge) |
| Team Lead, Gauntlet Orchestrator, Run Controller, Cognate runtime, Recursive Execution | Distinct roles, mechanisms and technique | The Team Lead delegates within a Team. The Gauntlet Orchestrator owns decomposition and the judgment on controlled work. The Run Controller advances that loop. Cognate hosts runs and effects. Recursive execution delegates a subproblem with a fresh work context. None supplies wider authority merely by dispatching. [W1](source-evidence.md#w1-cognate-workbench) · [G1](source-evidence.md#g1-gauntlet) · [E1](source-evidence.md#e1-pr-107) |
| Child Run, Expert Assignment, provider-internal child | Related, distinct | A runtime child run has its own observable lineage. Delegated Expert work has its own durable assignment. A provider-internal child may be opaque to the caller. Under PR #107’s design the caller would own assignment, authority ceilings, reservation and acceptance, and observation of a provider claim would supply no pre-approval. Gauntlet’s current result contract is a local precedent. [G1](source-evidence.md#g1-gauntlet) · [W1](source-evidence.md#w1-cognate-workbench) · [E1](source-evidence.md#e1-pr-107) |
| Runner, Execution World Provider, Model Provider, Recursive Execution Provider, Harness | Related, distinct | A runner carries out one execution through a selected mechanism. The world provider supplies its effect environment. A model provider supplies inference. A recursive provider carries out nested work. A harness defines the work scope and proof rules. A harness session may use any admitted mechanism. [C1](source-evidence.md#c1-cognate) · [G1](source-evidence.md#g1-gauntlet) · [E1](source-evidence.md#e1-pr-107) |
| Tool, Capability Contract, Permission Rule, Approval, Action Grant, Capability | Related, distinct | A tool exposes a request. A contract declares an effect. A permission rule conditions admission. Approval supplies a required decision. A grant authorizes the specific effect. CognitiveOS Capability is earned under variation. A registered or installed operation proves none of the later claims. [T1](source-evidence.md#t1-cognitiveos) · [C1](source-evidence.md#c1-cognate) · [S1](source-evidence.md#s1-sea-forge) |
| Capability, Capability Promotion, Affordance | Disposition, judgment, situated relation | Capability is demonstrated capacity. Promotion changes the standing of a claim about that capacity. A currently available Affordance depends on capability alongside the other six gates. [T1](source-evidence.md#t1-cognitiveos) · [A1](source-evidence.md#a1-godspeed-agent) |

## Consequence and context

| Concepts | Relationship | Boundary rule |
| --- | --- | --- |
| Observation → Evidence → corroborated evidence → Verification Result | Sequential judgments and transformations | An observation records what was seen. Evidence binds relevant observations to a question or criterion. Corroboration checks claims against their sources. A verification result reports the check against declared criteria. Each can be incomplete or disputed. [P1](source-evidence.md#p1-cep) · [R1](source-evidence.md#r1-realitytrace) · [S1](source-evidence.md#s1-sea-forge) |
| Execution Trace → Evidence Packet → Settlement Packet | Sequential, typed exchange | CEP distinguishes these profiles. A trace can supply material for evidence. A settlement packet carries a scoped judgment and its basis. SEA-Forge’s operation-level committed packet can serve as a Settlement Receipt. Ingest and display preserve issuer and finality. [P1](source-evidence.md#p1-cep) · [S1](source-evidence.md#s1-sea-forge) |
| Settlement → Controlled Run Settlement and Operational Settlement | Specializations, with different subjects and issuing authority | The generic theory is about consequence registering. Gauntlet judges a controlled run against its own frozen reference. SEA-Forge adjudicates a governed operation or declared work contract on the applicable path. A result from either can inform another context through a new evidentiary judgment. [T1](source-evidence.md#t1-cognitiveos) · [G1](source-evidence.md#g1-gauntlet) · [S1](source-evidence.md#s1-sea-forge) |
| Run completion, Assignment Acceptance, Task Acceptance, Candidate Promotion, Settlement Evaluation, Developmental Assessment | Related, distinct | Produced work, adoption, kernel-local finding and developmental update have different subjects, criteria and standing. An assignment can be accepted without accepting the encompassing Task. A verified candidate can remain unpromoted. Developmental Assessment uses consequence evidence and may later support Capability Promotion. [W1](source-evidence.md#w1-cognate-workbench) · [S1](source-evidence.md#s1-sea-forge) · [A1](source-evidence.md#a1-godspeed-agent) |
| Context Need → Context Packet → Context Bundle → working context | Sequential with optional projections | Retrieval answers a scoped need with references and completeness. An exchange bundle may cite or package that material. A running procedure consumes selected material as working context. The contracts give no equivalence between those outputs. Expert Memory is retained across work, and Developmental Memory requires a consequence-bearing effect on later navigation. [K1](source-evidence.md#k1-context-kernel) · [P1](source-evidence.md#p1-cep) · [W1](source-evidence.md#w1-cognate-workbench) · [T1](source-evidence.md#t1-cognitiveos) |
| Context Access, Proof Qualification, Operational Settlement | Distinct scoped judgments | Retrieval access concerns information disclosure. SWE_SEED’s proof and layer gates concern a work or assembly contract. SEA-Forge’s authority and operation-level settlement concern consequential work and its outcome. [K1](source-evidence.md#k1-context-kernel) · [Q1](source-evidence.md#q1-swe_seed) · [S1](source-evidence.md#s1-sea-forge) |
