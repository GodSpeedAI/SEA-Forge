| C-01 | BLOCKER | E §5 "Ingest: `agent-event-v1` ... extended" | The format cannot carry the profile. `sxr-cli/src/agent_event.rs:145-157` (origin/main) is a closed `ALLOWED` key list (no `world_ref`, `declaration_key`, actor, operation, `extensions`); `:258-264` rejects any other key; `RUNTIMES` (:122) is coding-agent names only, `KINDS` (:123-135) is session/tool/usage, plus token and benchmark-arm fields. Cognate's existing outbox does not use it: `cognate packages/realitytrace/src/types.ts:5-26` and `godspeed.ts:40-60` emit a CEP `execution_trace` envelope with `extensions`, and `Observation.semanticRef` is `{namespace,id:"ns::name",source{uri,digest}}`, not `world_ref`/`concept:` keys. Two ingest paths are conflated. Fix: pick the CEP-envelope path (`extensions["godspeed.interaction_event"]`), or specify `agent-event/v2` as its own WP with ADR; state which record kind each event becomes. |
| C-02 | BLOCKER | E §6 "Three-valued results map directly"; §4 `access policy_governed` | `domainforge validate --format json` cannot supply per-policy results. `src/cli/validate.rs:279-298` emits only `error_count` and `violations[]` (no TRUE results, no evaluated count); UNKNOWN differs from FALSE only by message text (`src/policy/core.rs:207-222`); `Violation.context` is `{}` (`violation.rs:28`), so no occurrence attribution. `graph/mod.rs:1075-1086` skips every operation-bound policy, so invariants declared via `access policy_governed by` per E §4 are never evaluated by `validate`. Path A as written is unbuildable; path B (classifier over AST JSON in `sxr-observed`) re-implements policy semantics, contradicting E §1 ("DomainForge owns policy semantics") and M§4. Fix: make a DomainForge change (per-policy JSON: policy id, tri-state, bound instance keys; opt-in to include operation-bound policies) a named prerequisite WP, or link `domainforge-core` as a library; keep invariants graph-evaluable. |
| C-03 | MAJOR | E §5-6 record kinds | `record_kinds.csv` (sxr origin/main) imposes anchors E omits. `observation.recorded` requires `run_id`, step/target refs and predecessors `committed plan` + `run.started`; `run.started` requires `repo_id;checkout_id`; `semantic.snapshot` requires repo/checkout/checkpoint hash; `residual.computed` requires Question + snapshot + target refs, predecessor "snapshot; plus qualifying Evidence/Settlement"; `diagnostic.settled` needs a declared Threshold and `proposal.raised` for repairs needs `diagnostic.settled`.
