## Decisions where E is silent or contradictory

Items 2 to 12 marked below were **accepted in review 2026-11-14** except where the Review amendments section changes them (1 and 12 in part).

1. **E §5 "`expectation_ref` | string | evaluated: yes | RealityTrace question / threshold ids"**: typed as one string `question:...` or `threshold:...`. The plural "ids" suggests an array; open question.
2. **E §14 "`executor_provenance` and `kind` are carried on events"**: `kind` (evaluated|exploratory) is a required event field; it is the discriminator for "evaluated: yes".
3. **E §5 `emitter.signature` "yes from WP-33"**: optional object, closed `{key_id, alg, sig}`; `alg` any non-empty string. Signed over the canonical extension without `emitter` (CEP-0008 §16.5).
4. **E §2 "episode_ref ... digest over the frozen-reference body (`case_id`, `plan_item_id`, `n`, `world_ref`, criteria, evidence sources; it does not contain `episode_ref`)"**: read as non-exhaustive. `body` also holds `kind`, `executor_provenance`, `decision_maker` and `coverage_manifest`, because E §5 says the coverage manifest is "frozen with the episode" and NT-13/NT-17 need kind and result-exclusion inside the digest. Document shape `{episode_ref, body}`; closed body so a result field is refused (NT-17).
5. **E §3 "`episode.frozen {episode_ref, canonical reference, digest, kind, executor_provenance, coverage manifest}`"**: payload is `{episode_ref, reference, digest, realitytrace_refs}`; kind, provenance and manifest travel inside `reference.body` so they cannot differ from the frozen copy. `realitytrace_refs` (plan, questions, thresholds) added from E §5 "(2) the case record `episode.frozen` referencing them".
6. **E §3 `episode.settled {..., reliability, independence, ...}`**: types not given. `reliability` is an object over the SOP §7.7 dimensions T A I K D X N (strings, `{}` valid); `independence` is `{independent_source_count, verifier_context fresh|shared|unknown}` (from E §5 and I-2 "verifier's context is recorded as fresh"). The settling principal is the authenticated principal, not a payload field.
7. **E §3 `{kind, payload, idempotency_key}`**: request closed to exactly those three fields (no `case_id`; the SFWP route carries the case). `idempotency_key` is the `(system, record_id)` key written as one whitespace-free token. A replay returns the original response with `replayed: true`; same key with a different body is `IDEMPOTENCY_CONFLICT`. I-3 (`FREEZE_KEY_EXISTS`) applies to a second freeze under a different idempotency key.
8. **Codes**: reused G's names where G gave them (`FREEZE_KEY_EXISTS`, `FREEZE_MISSING`, `FREEZE_INCOMPLETE`, `SELF_SETTLEMENT_REFUSED`, `RESULT_INVALID`, `ANCHOR_PREDATES_FAILED`, `MODEL_ANCHOR_LATE`); I-1 refusals at append level are FREEZE_MISSING (settle with no freeze) and FREEZE_INCOMPLETE (freeze naming absent RealityTrace records). New: `SCHEMA_INVALID`, `KIND_UNKNOWN`, `IDEMPOTENCY_CONFLICT`, `EPISODE_REF_DIGEST_MISMATCH`, `ANCHOR_TAG_MISMATCH`, `ANCHOR_RECEIPT_MISMATCH`, `PROFILE_DUPLICATE_KIND`, `REP_*`. `KIND_IMMUTABLE` (NT-13) not used: a relabel is a second freeze for the key.
9. **E §5 "signed annotated tag `fde-anchor/<kind>/<id>`"**: kinds `model|freeze|prereg` (from "model registration, each freeze and pre-registration"). An `episode_ref` contains `:`, illegal in a git ref, so `id` is a ref-safe token and the real subject is `subject_ref` plus `digest`. `pusher.credential_scope` (`shared_os_user|dedicated_anchor_credential`) encodes RD-26/OD-6.
10. **E §6 "per kind: quantifier, `k`, deadline, class mapping"**: kinds are the two expectation kinds plus the four of the "Cannot be classified by policies" table (ordering, frequency, absence, timing); context variation is not a kind. Added `comparison` per kind and `allow_vacuous_truth` (RD-08 "unless the profile says so"). Deadlines are `sequence_steps|causal_hops` ("emitter clocks never decide"). Class mapping is constants fixed by E §6.
11. **E §6 observed representation**: shapes of ordering statistics, distributions, authority outcomes, coverage and uncertainty are not given. Chosen: per-system first/last sequence; role and plan-item count maps; `authority_outcomes` by class of `decision_id` plus a separate `outcome_status` count; `independent_occurrence_count` per node (E §5 independence rule); coverage rows `{emitter, event_kind, observed_count, status}`; uncertainty `{rejected, unverified}`. Occurrence id is `<system>:<record_id>` (E §2 key). Hash fields use `sha256:<hex>`.
12. **E §6 residual**: basis values are only partly named by E. Chosen per class (table in the README), from E §6, RD-03, NT-06, E §5; `evidence_source_silent` from G NT-06, `executor_only_evidence` from E §5. Added `profile_id` (needed to check `below_minimum_support` against `k`) and `evidence_refs` (NT-45 "residual without evidence refs").

## Open questions

- RD-08 says the comparison profile is "frozen with the episode", but E's frozen-reference field list has no profile reference. Should `body` carry `profile_id`?
- Should a residual and a representation carry each other's id or hash (AT-08 "representation hash differs")? E lists neither.
- The algorithm of `input_set_hash` is WP-16's; only its format is fixed here.
- CEP's own validator (`cep.schema_value`) has no `integer` type, so the interaction-event fixtures are checked with the standard `jsonschema` library only (DEBT-IE-01).
- Does an exploratory frozen reference need `falsifiers` (>= 1)? The schema requires it for both kinds.
- `rfc8785` added as a CEP dev dependency (CEP `uv.lock` updated); no dependency added in SEA-Forge or RealityTrace.
- The SEA-Forge and RealityTrace tests canonicalise ASCII integer/string values with a small helper; the full RFC 8785 rule is verified only in the CEP repository.

## Review amendments (2026-11-14, same v1 files; commits CEP 8b6fc90, SEA-Forge 838754bf, RealityTrace 6711402)

1. **Comparison profile frozen with the episode.** `frozen-reference` `body` has a required `comparison_profile {id: profile:..., sha256}` inside the digest (RD-08). Invalid fixtures: `comparison-profile-missing`, `comparison-profile-digest-malformed`, `comparison-profile-id-not-prefixed`. Supersedes the first open question. (Fixtures regenerated, so every `episode_ref` digest changed.)
2. **Residual to representation, one way.** `residual` requires `representation_id` (`representation:...`) and `input_set_sha256` (`sha256:<hex>`, same format as the representation's `input_set_hash`). The representation does not reference residuals. Invalid fixtures: `representation-id-missing`, `input-set-sha256-missing`, `input-set-sha256-malformed`, `representation-id-not-prefixed`. Supersedes the second open question.
3. **Falsifiers by kind; exploratory settlement.** `criteria.falsifiers` is required in both kinds, non-empty for `evaluated` (`if kind = evaluated then minItems 1`), may be empty for `exploratory`. Fixtures: `evaluated-falsifiers-empty`, `exploratory-falsifiers-missing`; valid `exploratory-live` has `[]`. `case.record.append` gains refusal `EXPLORATORY_NOT_SETTLEABLE` for `episode.settled` with `result` S or F on an episode whose frozen kind is exploratory (U and C are accepted). The payload could already express this (`result`; the kind is read from the freeze record), so no shape change; I read "confirmed/contradicted" as the S and F results. Fixtures: valid error, exploratory frozen/settled-U requests; invalid `error-exploratory-not-settleable-carries-invariant`; scenarios `exploratory-settled-success-refused`, `exploratory-settled-failure-refused`, `exploratory-settled-unresolved-accepted`. Supersedes the third open question.
4. **`expectation_refs`.** The interaction event field is an array of `question:`/`threshold:` strings, key required when `kind` is evaluated, may be empty. Uniqueness cannot be a schema keyword: CEP's own validator rejects `uniqueItems` ("unsupported schema keyword", which fails `cep validate all`) and the validator is not to be changed, so uniqueness is a semantic rule checked by the contract test (`IE_EXPECTATION_REFS_DUPLICATE`, fixture `expectation-refs-duplicate`) and logged in DEBT-IE-01. Supersedes decision 1 and the first open question.
5. **Accepted in review 2026-11-14:** body contents (decision 4), `episode.frozen` payload (5), `reliability` / `independence` shapes (6), request shape and idempotency (7), error codes (8), ref-safe anchor tag ids and `credential_scope` (9), profile kinds (10), RealityTrace ordering, distribution, coverage and uncertainty shapes (11), residual basis shapes (12), and decisions 2 and 3.
6. RealityTrace `.agents/` untouched. DEBT-IE-01 kept (now also records `uniqueItems`); the CEP validator is unchanged.
7. SEA-Forge test canonicaliser now returns an error on non-ASCII text, non-ASCII keys and non-integer numbers, with a comment and test `the_test_canonicaliser_refuses_input_it_cannot_hash_faithfully`. The SEA-Forge and RealityTrace READMEs say full RFC 8785 conformance is tested in the CEP repository only. (The RealityTrace test does no canonicalisation, so it needed no helper change.)

Remaining open questions: input_set_hash algorithm (WP-16); the CEP validator gaps (`integer`, `uniqueItems`).
