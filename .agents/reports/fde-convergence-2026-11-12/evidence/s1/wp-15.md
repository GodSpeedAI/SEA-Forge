## Mapping to the schema (what each field is)

- world_ref, semantic_ref (the invocation's own contract `semanticRef` when it has one, else the case's), declaration_key (derived), actor.principal (caller actor id) and actor.role (case context), operation (capability id, or the run event type), resource (`capability:<id>` or `run:<runId>`), context.case_id/plan_item_id/episode_ref/assignment_id, correlation (structured, with run_id), causation_id (the event's causationId), authority.decision_id, outcome.status, source.{system "cognate", record_id, sequence, recorded_at}, executor_provenance, kind, expectation_refs (evaluated only; `[]` when none).
- authority.decision_id: the SEA-Forge decision envelope id when a governed decision was recorded; `unknown` for an invocation with no recorded decision; `not_required` for run-level events and local-policy decisions without a SEA-Forge authority. Never fabricated.
- executor_provenance: the case context's flag (default `live`); `program.run` invocations are always `program`.
- `emitter` is absent: unsigned in S1, as the schema allows before WP-33. No signature is produced anywhere.

## AT-05 (runtime part): what is demonstrated here

- 100 % of the case-run events a test run produces (invocations of an ordinary capability and of `program.run`, plus `run.completed` and `run.failed`) validate against the pinned v1 schema and carry all 13 required fields, evaluated and exploratory forms. Test: `evaluated run: every observation validates...`.
- Every `source.record_id` equals the id of a committed event in Cognate's own store (resolved in the test against `service.events`). Resolution at the owning system by RealityTrace (WP-16) is not exercised here.
- correlation is an object, never parsed from a string; `run_id`, `case_id`, `assignment_id`, `episode_ref` are separate fields.
- Duplicate replay: a port that records then throws (receipt lost) forces redelivery; the target ends with one record per event, the extension is byte-identical on every attempt, and the outbox holds one intent per event with id `observation:<record_id>`.
- Non-case run: no `caseContext`, no observation intent, no interaction event; the existing suite is unchanged.

## Deviations from E / the schema, and known limits

1. Events covered: `run.invocation`, `run.completed`, `run.failed`. `run.started` and `run.cancelled` are committed by the service, not the executor, and do not pass through `outboxFor`; they emit no interaction event (a host hook that today ignores them stays unaffected). Not done.
2. `actor.principal` is the run starter (the caller). Invocations by a nested actor are not separately attributed.
3. The case context is passed on the in-process `startRun`. It is not exposed in the Connect/proto wire request. Not done.
4. `authority.decision_id` is not verified here (RealityTrace's job); `not_required` is Cognate's own claim for run-level events and local-policy decisions.
5. No RFC 8785 hash is computed: nothing is signed in S1 and the hash rule belongs to WP-11/WP-33. The vendored schema is pinned by file sha256 only.
6. The interaction event for an ungoverned case run rides `Observation.interactionEvent` rather than a CEP envelope, because the `godspeed.execution_trace` profile requires an authority decision reference; only governed events carry a trace with the extension attached.
7. `program.run` v1 edits existing text files only; create, delete, rename, binary and CR-ending patches are refused. No fuzz or offset matching. Symlinks inside the workspace that point outside are not detected (the local provider's `resolve` is lexical, as for every `filesystem.*` capability). No environment override is accepted.
8. A run in a case is not forced to wire `interactionOutboxFor`: a host that supplies its own `outboxFor` (or none) emits nothing. The runtime default is unchanged so non-case behavior is identical.
9. The `bun.lock` gains the realitytrace devDependencies (ajv, execution, runtime-api, runtime-bun, all already in the lock).

## Follow-up (symlink confinement, write-failure rollback, run.started/run.cancelled)

Worktree `~/projects/_wt/fde-cognate-integration`, branch `fde/integration`, on top of `ec9b28f`.

### 1. Symlink confinement in `program.run` (`packages/execution/src/program.ts`)
- `FileSystemPort` gains optional `realPath(path)` (`types.ts`); the local world implements it with `fs.realpath` (`local.ts`). `assertReal` requires the real path of each patch target and of `cwd` to equal the real workspace root plus the same relative path. So a symlink anywhere along a path is refused with `path_escape`: a file link or directory link pointing outside, a symlinked cwd, and (documented decision) a symlink that stays inside the workspace.
- A workspace root that is itself reached through a symlink still works (the real root is resolved first).
- Checks run at plan time, again immediately before each write, and for `cwd` again after the writes and before the command (a failure there rolls the patch back). Residual: a link swapped in by a concurrent process between the last check and the write is not excluded; the port has no no-follow write. Worlds without `realPath` (memory, POSIX-script worlds, which guard symlinks in their own IO) skip this check.
- Tests (`packages/execution/test/program.test.ts`, 22 total): outside file link, outside directory link, symlinked cwd, in-workspace links (file and directory), root via symlink, plan-time refusal with zero writes, cwd refused before any write, target swapped after planning (caught before write, outside file untouched), cwd swapped after the writes (caught before the command, patch rolled back).

### 2. Write-failure rollback
- Fix: the file whose write fails is now restored too (it may be partly written); previously only fully written files were. A restore that itself fails is reported in the error (`could not restore: <paths>`), not swallowed.
- Guarantee: if all restore writes succeed, the tree equals its original. There is no atomic rename (the port offers none), so a crash mid-write is not covered.
- Tests: injected failure on the second file after a torn write (first and second restored, command not run); restore failure reported.

### 3. run.started and run.cancelled
- `runtime-bun/src/service.ts`: both events get a pre-assigned id and go through `core.outboxFor` in the same commit (`streamSequence` 1 for started, `events.length + 1` for cancelled). The case context is copied onto `run.cancelled` metadata from `run.started`. `INTERACTION_EVENT_TYPES` now has five types; status is `succeeded` for started, `interrupted` for cancelled. Non-case runs add no intents. A host `outboxFor` is now also called for these two events (it returns `[]` when it does not care).
- Test: "AT-05: 100 % ..." enumerates every event type a case run produces (including a cancelled run, with a duplicate cancel redelivery). Each type must be in `INTERACTION_EVENT_TYPES` or in an explicit `NON_CONSEQUENTIAL` list, otherwise the test fails (a new event type cannot slip through). Every interaction event must have exactly one valid extension with `source.record_id` = its event id, and the observation count must equal the interaction event count. A non-case start/cancel emits nothing.
- Limit: `NON_CONSEQUENTIAL` (state.changed, run.step.completed, run.recall, run.artifact, run.waiting, ...) is a classification I made; those types are not extended. Not exercised: the wait/artifact types are not produced by the test agents.
