## Deviations and decisions (E and the contracts are silent or differ)

1. `representation_id` is not a field of `observed-representation.v1` (closed schema). `observed derive` prints a wrapper `{representation_id, representation_hash, input_set_sha256, window, representation}`; `representation` validates against the contract. `representation_id = representation:sha256:<hash of canonical representation>`; `input_set_sha256` equals the representation's `input_set_hash`. Coverage window is explicit in `window` (`until`, `first_ordinal`, `last_ordinal`, `record_count`, `head_entry_hash`) and inside the input-set hash.
2. `input_set_hash` algorithm (open question in WP-11): SHA-256 over canonical JSON of `{contract, selectors, options, window, inputs (sorted entry hashes of included occurrences), rejected, unverified}`.
3. Canonicalisation: `sxr_core::canonical_json` (byte-order key sort, serde_json numbers) equals RFC 8785 only on the I-JSON domain; `canon.rs` refuses floats, integers beyond 2^53-1 and non-BMP object keys (`CANONICALIZATION_REFUSED`). Full RFC 8785 conformance is still tested only in CEP.
4. Extra rejection codes `INGEST_REJECTED_SCHEMA` and `INGEST_REJECTED_SIGNATURE` (not in G). Identity is checked before schema so a missing `world_ref`/`declaration_key` is `INGEST_REJECTED_IDENTITY`.
5. Accepted events are stored as `observation.recorded` (`extensions["godspeed.interaction_event"]` untouched, plus `extensions["sxr.ingest"] = {accepted, signature_status, occurrence_id}`; `run:` subject is `correlation.run_id` or `unscoped`). Rejections are `ingest.rejected` with `extensions["sxr.ingest_rejection"]`. No record kind changed; `.csv` registry untouched. Derive re-validates (schema, source resolution, ingest note) and counts failures as `unverified_event_count`.
6. Source-record resolution: `source.record_id` must equal an `evidence.recorded`/`evidence.created` evidence id (or that id minus the `evidence:recorded:` / `evidence:` prefix) in the ledger. `source.system` is not matched against the evidence's producer.
7. Signature hook is trait `SignatureCheck`; S1 default `UnsignedOnly`: no signature gives `unsigned`; a present signature it cannot check gives `unverified`; neither is ever `verified`.
8. Extra CLI inputs (not in the brief, needed by the contract): `--repo` (ledger), `--profile` (default `profile:s1-default`; the representation requires `profile_id`, and the frozen reference is not reachable from RealityTrace), `--declared` (declaration keys of the pinned world; others become `undeclared:<sha256 of operation\nresource>`), `--coverage-manifest` (frozen manifest rows `{emitter, event_kind}`, `event_kind` = event `operation`; without it rows are the observed pairs and an empty result is `COVERAGE_UNDEFINED`), `--independent-system` (repeatable; default none, so `independent_occurrence_count` is 0, the conservative direction). `observed ingest --repo --file` is also new and appends; `derive` never writes. `--until` takes `head` (default), an append ordinal, an entry ULID or an RFC 3339 time compared with the ledger's own `committed_at`.
9. Edges: links are adjacent pairs per owning system by `(sequence, record_id)` plus causation links (`causation_id` naming a record of the same system); a pair found both ways counts once, as causation. Edge distributions are taken at the `to` occurrence. Sequences are never compared across systems.
10. `ledger.db` open: derive opens with `tail_verify_on_open = 0` and runs the full-chain check itself, so every verification failure is `CHAIN_VERIFY_FAILED` (exit 5). `Ledger::open` otherwise fails first with an untyped integrity error.

## NOT done

- `declaration_key` is checked for shape (`concept:<uuidv5>`) only; it is not recomputed from `semantic_ref` nor resolved against the pinned world's semantic snapshot (E section 2, RD-22). The uuid namespace is DomainForge's; not available here.
- `authority.decision_id` is not verified against SEA-Forge (E section 5); no emitter signature verification (WP-33); independence is declared by flag, not read from a frozen manifest.
- Coverage manifest is a CLI file, not read from the frozen reference or case record.
- Truncation of the ledger tail (deleting the last record) is not detectable by a hash chain alone (CEP-0008 section 55: tamper-evident, not tamper-proof); NT-03b tests a middle row and an altered row. A head anchor would close it (not built).
- `representation.recorded` is not written; derive emits to stdout/`--out` only (per the brief).
- `observed compare`, residuals, class changes (WP-17) not started. The "class changes to contradicted" half of NT-03 and "residual changes class or disappears" half of AT-08 are therefore not demonstrated.
- Release plumbing for the new crate (`scripts/publish-crates.sh`, `.github/release-please-*.json`, docs/source-map entries) not updated; `realitytrace` now depends on unpublished `sxr-observed`. AT-xx gate wiring in `scripts/fde-proof.sh` (WP-19) not done.
- `.agents/` status files untouched.
