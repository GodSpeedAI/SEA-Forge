## Decisions and deviations (E and the contracts are silent or differ)

1. `residual.v1` is closed and has no field for context, facts hash, DomainForge version or exploratory flag. Brief asks to record the facts hash "in the residual": not possible without changing the contract, so it is `annotations[residual_id].facts_sha256` and `evaluate.facts_sha256` in the result document (same wrapper pattern as WP-16). Context distribution is in `annotations[residual_id].context`.
2. The representation holds counts, not per-occurrence data (operation, resource, sequence, causation). Compare therefore takes the ledger too (`--repo`), re-reads occurrences by id inside the representation's window, and checks the representation (id recomputed, schema, window end hash and count) against that ledger. It does not re-run derive.
3. `--mapping` (E section 6) has no contract; I defined `compare-mapping.v1` as an input document (contracts/README.md section 5): operation-to-input-field specs, expectations (policy_evaluable, structural flow/precondition, absence), and the evidence sources each depends on. The frozen evidence source list names a `system`; "emitted nothing" is no occurrence in the representation whose `source.system` equals it.
4. `proposed_result` (S/F/U) is computed from the episode list only and is a proposal. NT-06's "result U" is that field. Which list a kind feeds comes from the profile's `comparison`.
5. Policy expectations over zero occurrences are `insufficient` / `below_minimum_support` (RD-08), not `not_exercised`; only absence expectations with no observed trigger and declared keys never observed are `not_exercised`.
6. `ordering`, `frequency`, `timing` expectations are not implemented: reported `insufficient` / `not_evaluable`, never decided.
7. Only `operation_inputs` facts are generated (operation-bound policies). Graph policies over instances (`instances` in the facts file) are not generated.
8. `--declared <snapshot_id>` is a free string recorded in each residual; there is no snapshot store to resolve it against.
9. The `evaluate` ambiguity and order rules need no code: the facts file is canonical JSON sorted by (operation, occurrence id), inputs are keyed by `<system>:<record_id>`; DomainForge rejects ambiguous operation names (surfaces as `EVALUATE_FAILED`).
