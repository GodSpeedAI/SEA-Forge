## Decision basis

The Workbench builds and its unit/component tests pass, but the available browser suite fails 2 of 3 tests and the native Tauri/server path was not available, so this is a mocked frontend evaluation rather than integrated completion. The readiness, identity header, Thoth composer, asset catalog, case horizon, approval inbox, operations monitor, delegation preview, installation contract, and run-record routes are reachable; several other canonical routes explicitly render as unbacked because their SFWP methods are absent. Hard gates G1, G3, G4, G5, G6, G7, G8, G9, G11, G12, G13, G14, and G15 fail because the protected-action boundary, typed denial context, source-record traceability, state vocabulary, recovery, separation of duty, and spendable capability coverage are incomplete. The most consequential runtime finding is that a ready readiness projection plus unresolved identity renders an enabled “Create case” control with no identity-specific explanation. The 128-story result is 5 PASS, 45 PARTIAL, and 78 FAIL; representative scenarios are all partial or failed, so the numerical score cannot override the hard-gate failures.

Evidence keys: B1 = `bun run check`, `bun run build`, and `bun run test` results; B2 = `bunx playwright test e2e/readiness.spec.ts --workers=1` result (1 passed, 2 failed); B3 = direct browser probe against `http://127.0.0.1:1420` using the checked-in degraded readiness fixture, including direct navigation and refresh; B4 = contract-shaped deterministic mock browser probe across 15 routes, Thoth ask, axe, narrow viewport, and console capture; B5 = deterministic `run-01JABCDEF` browser fixture showing exit code 0 beside rejected settlement and criterion evidence; B6 = deterministic ready projection with `identity.available=[]`, where “Create case” observed `disabled=false` and no disabled reason; B7 = `?guardSimFail=G9` denial probe showing guard id, fail-closed status, and “Open readiness console”; B8 = source/runtime route inventory, especially `SurfacesPages.tsx`, `UnbackedSurface.tsx`, `ReadinessPage.tsx`, `ApprovalInboxPage.tsx`, and `CaseCreationWorkbench.tsx`. The score components are 15.0 story, 3.1 scenario, 6.0 accessibility/interaction, and 3.0 visual/terminology points.
