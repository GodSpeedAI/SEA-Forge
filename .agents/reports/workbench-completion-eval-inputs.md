## Real temporary-cell setup and application start

Use an explicit temporary root and socket; do not use a real operator cell.
The seed recipe creates records only through the production kernel and is safe
to reset only at its marker-bearing root.

```sh
SEA_FORGE_DEMO_SOCKET=/tmp/sea-forge-workbench-eval.sock just cell-seed /tmp/sea-forge-workbench-eval-cell
SEA_FORGE_DEMO_SOCKET=/tmp/sea-forge-workbench-eval.sock just workbench-demo /tmp/sea-forge-workbench-eval-cell
```

The second command starts the packaged desktop application and has it supervise
the packaged `sea-forge-server` sidecar. It is intentionally an interactive
desktop start command, not a Vite URL. After the evaluation, close the desktop
application and run:

```sh
just cell-reset /tmp/sea-forge-workbench-eval-cell
```

## Test identities and records

`cell-seed` binds the current Unix uid to `operator_a` and `operator_b`, both
with the `operator` role. It creates an accepted run, a denied run, a pending
approval raised by `operator_a`, a self-approval refusal for `operator_a`, and
an approval resolved by `operator_b`. The duplicated local binding is a
deliberate ambiguity fixture: until the renderer exposes an explicit actor
choice, protected UI actions must surface `identity_unresolved` rather than
selecting an actor by array order. Inspect calls remain available without an
actor.

The packaged-stack host tests additionally exercise a single-actor cold cell
(`operator_a`) and a real sidecar over an owner-only socket. These two fixture
shapes let the evaluator distinguish unresolved identity from a missing server
or an invented renderer identity.
