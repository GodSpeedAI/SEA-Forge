## Context

The product has three operator surfaces (CLI, server, Workbench) that must agree on
where the cell root is and where the Unix socket lives. Today they disagree: the
server resolves relative to CWD, the desktop resolves under `$HOME`. No surface
installs or version-matches the others.

### User-decision checkpoint (U-06)

The owner's sidecar-vs-separate-service decision (U-06) changes deployment
configuration. This packet proceeds on the **reversible provisional default**
recorded in `DECISION_REGISTER.md` P-01/P-03: a separately installed local
server binary, with the Tauri host connecting to it through one documented
socket path. This is the smallest evidence-supported artifact set and does not
foreclose a later sidecar decision — the SFWP contract, cell root, and socket
path are identical either way.

If the owner selects sidecar supervision before SF-012, only the process-lifecycle
wiring in SF-012 changes; SF-001's contract is preserved.

## Required outcome

One cell-root and socket contract, documented and enforced, shared by all three
surfaces, with no CWD/Home mismatch.

## Current evidence

- `crates/sea-forge-server/src/config.rs:24-32` — `default_socket_path` and
  `default_root` are independent fields; setting `SEA_FORGE_ROOT` does not move
  the socket.
- `workbench/apps/desktop/src-tauri/src/lib.rs:44-50` — host defaults to
  `$HOME/.sea-forge/server.sock`, independent of any server config.
- `workbench/apps/desktop/src-tauri/tauri.conf.json` — `targets: all`.

## Implementation boundaries

- Compose a relative `socket_path` under `root` in `ServerConfig`; honor
  absolute paths as explicit overrides.
- Align the Tauri host's `resolve_socket_path()` to the same root-anchored
  default.
- Restrict `tauri.conf.json` bundle targets to Linux + macOS.
- Do NOT implement process supervision (sidecar spawn) here — that is SF-012.

## Acceptance scenarios

1. Server started with `SEA_FORGE_ROOT=/tmp/cell` places both records and
   socket under `/tmp/cell/`.
2. Workbench started on the same host connects to `/tmp/cell/server.sock`.
3. A second server started on the same root fails with a typed
   `socket_in_use` error, not a crash.
4. `system.hello` returns matching protocol versions from both CLI and host.

## Verification procedure

```sh
cargo test -p sea-forge-server config
cargo test -p sea-forge-server --test conformance_sfwp
cargo build --manifest-path workbench/apps/desktop/src-tauri/Cargo.toml
```

## Integration notes

This contract is a prerequisite for SF-002 (fail-closed startup uses the resolved
root/socket), SF-005 (identity resolves at the host/server boundary using the
same cell), and SF-012 (packaged E2E depends on one install procedure).

## Known traps

- Do not break the `SEA_FORGE_SOCKET` override used by tests/dev
  (`src-tauri/src/lib.rs:45-47`).
- Existing tests may depend on CWD-relative defaults; update them to use the
  root-anchored resolution.

## Definition of done

All three surfaces resolve one root and one socket from one documented
procedure, the bundle config does not over-advertise platforms, and a
conflicting second server fails safely.
