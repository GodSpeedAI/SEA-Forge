## Context

The server currently swallows configuration errors and discards reloads. A
silent default can change the cell root, socket path, or policy digest without
the operator knowing. The lack of a request timeout means one long case commit
can starve inspection and recovery.

## Required outcome

Startup, reload, and request handling all fail closed with typed, recoverable
errors. No invalid configuration produces a running server under unintended
defaults.

## Current evidence

- `main.rs:24-30` — `unwrap_or_else` falls back to `ServerConfig::default()`.
- `lib.rs:1455-1461` — `if let Ok(new_config) = state.reload_config() { let _ = new_config; }`.
- Connection handler (in `lib.rs` `run`/`serve`) — no `tokio::time::timeout`
  around individual request handlers.

## Implementation boundaries

- Touch only `main.rs`, `config.rs`, `lib.rs`, and focused integration tests.
- Do not weaken sandbox fallback or change policy evaluation semantics.
- Preserve the first-run case (absent `server.yaml` is valid).

## Acceptance scenarios

1. Malformed YAML, invalid agent endpoint, non-existent sandbox, policy parse
   error, DomainForge version mismatch, and socket-in-use each produce a typed
   startup error and non-zero exit.
2. A valid `server.yaml` change followed by a protected request triggers a
   reload that affects the next dispatch.
3. An invalid reload retains the last-known-good config and publishes a typed
   `config.reload_failed` event.
4. A handler sleeping 15s returns a timeout response at 10s; the request's
   durable status is recoverable via `request.get_status`.

## Verification procedure

```sh
cargo test -p sea-forge-server -- --test-threads=1
cargo test -p sea-forge-server --test conformance_sfwp
```

## Integration notes

SF-008 (readiness slice) depends on preflight results being visible. SF-012
(packaged E2E) depends on startup failing safely. SF-006 (idempotency) depends
on the timeout preserving request status.

## Known traps

- Do not cancel the underlying work on timeout — return a timeout *response*
  and let the work complete in the background; only the *response* is timed out.
- Preserve test isolation: some tests start a server without a `server.yaml`;
  the absent-file path must remain `Ok(default)`.

## Definition of done

Every invalid-config and unavailable-preflight case blocks startup; reload is
atomic with a typed failure event; the 10s timeout preserves recoverable status.
