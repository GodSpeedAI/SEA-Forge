## Corrections applied during execution

Recorded per the authority hierarchy (canonical spec and architectural
invariants outrank this packet's prose).

1. **`K-02` is not an architectural invariant.** The `architectural_invariants`
   list above names it; `docs/execution/ARCHITECTURAL_INVARIANTS.md` defines no
   such identifier. The reference is dangling and was not enforced. The
   invariants this packet actually governs are AUTH-01, AUTH-03, DOM-01, DOM-02,
   DOM-03, DATA-01, and K-01.

2. **The run directory is a governance record location, not an execution side
   effect.** Acceptance criterion 2 requires "only governance records
   (decision+trace+evidence of denial)" on the deny path — which is only
   possible if `runs/<run_id>/` exists to hold them. AUTH-01 is enforced on
   `workspace/` and `artifacts/`, the only directories the *operation* would
   touch. `case_dispatch.rs` creates `run_dir` before evaluation and
   `workspace`/`artifacts` inside the Allow branch.

3. **The CLI path was deliberately left alone.** `cli/src/pipeline.rs:275-291`
   creates `workspace/` before authority as part of its run-record scaffold, and
   `justfile:386-389` pins that behaviour by asserting a denied CLI run still has
   an existing empty `workspace/`. Changing it was out of this packet's
   `allowed_paths` and would have broken P1-P4b. The server and CLI therefore
   differ on this one point; the server is the stricter of the two.

4. **`sea_forge_settlement::settle` returned a constant id.**
   `sea-forge-settlement/src/lib.rs:120` hardcoded `settlement_id: "set_01"`
   while every other settlement site in the workspace
   (`case-runner:183,218`, `cli/plan_pipeline.rs:601`, `server/lib.rs:364`,
   `self-model/store.rs:403`) mints `ids::random_id("set")`. Routing this
   packet's dispatcher through `settle` would have spread that constant to the
   server, where a `settlement_ref` naming `set_01` would have matched every
   settlement in the cell at once. Fixed at the source, in its own commit,
   with `two_settlements_are_distinguishable`.

- **Run-level `authority.json` / `settlement.json` materialization and authority

  them is a refactor with no behavioural requirement behind it.

## Context

The canonical governed lifecycle exists and is proven in the CLI path
(`pipeline.rs`, `plan_pipeline.rs`). The server's case dispatch bypasses it for
sandbox episodes via a local shortcut (`execute_sandbox`). This is not a missing
feature — it is a wiring defect that creates pre-authority side effects and
exit-code settlement, violating the product's central invariants.

## Required outcome

Every sandboxed case episode — whether triggered by CLI, SFWP, or Workbench —
flows through the same authority→trace→evidence→settlement pipeline. No side
effect precedes a committed Allow. Settlement evaluates criteria and evidence,
never exit code alone.

## Current evidence

The shortcut at `case_dispatch.rs:497-609`:
- Lines 513-521: `fs::create_dir_all(&workspace)` and `&artifacts` before
  `engine.evaluate` (line 530).
- Line 543: `domainforge_candidate: None`.
- Lines 587-594: `status = if Allow && Completed && exit_code==0 { Accepted } else { Rejected }`.
- Lines 600-604: `basis = ["execution_completed"]` or `["authority_denied"]`.

The correct pattern at `pipeline.rs:474-599`:
- Per-operation authority evaluation with DomainForge candidate (lines 486-516).
- Trace `AuthorityEvaluated` (lines 517-521).
- Evidence prepare + commit (lines 522-540).
- Decision committed to ledger (lines 543-559).

## Implementation boundaries

- **Sole ownership of `case_dispatch.rs`.** No parallel packet edits this file.
- Reuse `CaseRunner`, `PolicyAuthorityEngine`, `JsonlTraceRecorder`,
  `JsonlEvidenceWriter`, the settlement crate, and `LedgerStream` — do not
  duplicate them.
- Preserve `execute_agent`'s delegation path (it already uses the full
  delegation pipeline with basis reuse).
- Do not change minimum CLI record schemas, ID grammar, or exit codes.

## Acceptance scenarios

1. **Allow + exit-zero + criteria met** → Accepted, with trace, evidence,
   settlement, and capability records all present and cross-linked.
2. **Allow + exit-zero + criteria unmet** → Rejected (false success caught).
3. **Deny** → no workspace/process/network mutation; decision + trace +
   evidence of denial committed.
4. **Escalate** → approval request created, no side effect.
5. **Timeout** → Rejected with timeout evidence.
6. **DomainForge drift** → pre-authority typed rejection.
7. **P1-P4b** → still green.
