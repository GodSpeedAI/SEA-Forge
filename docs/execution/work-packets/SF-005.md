## Context

The Workbench fabricates identity. The server defaults to `operator_local`.
Neither can satisfy the authority invariant that every protected action is
attributed to a resolved actor with enforceable separation-of-duty.

## Required outcome

The Tauri host resolves local installation identity and attaches it to SFWP
commands. The server enforces its presence on protected verbs and records it in
authority, approval, and audit records. The Workbench displays server-resolved
identity, not fabricated constants.

## Current evidence

- `router.tsx:38-51` — `mockGuardContext` with hardcoded actor/policy/integrity.
- `case_dispatch.rs:525-528` — `Actor { actor_id: entity, role: Operator }`.
- No SFWP verb returns resolved identity.

## Implementation boundaries

- Server-side: add actor fields to the SFWP `Request` type (additive,
  optional for inspect, required for command). Validate in dispatch.
- Host-side: `bridge.rs` attaches resolved context to commands.
- Renderer: replace `mockGuardContext` with a `useReadiness`-backed session.
- Do not implement remote/multi-user authentication (K-08, U-03).

## Acceptance scenarios

1. Operator submits a case; approver approves; both identities in records.
2. Same actor submits and approves → SoD denial.
3. Protected verb without identity → typed denial, no effect.
4. Inspect verbs work without identity (backward compatible).
5. UI readiness shows resolved actor, policy digest, integrity status.

## Integration notes

SF-008 (readiness slice) surfaces the resolved identity. SF-009 and SF-010
depend on actor context being present. This packet must land its SFWP contract
before SF-006 adds idempotency to the same request layer.

### User-decision checkpoint (U-07)

The public SFWP identity/session contract is a user decision. This packet
proceeds on a **reversible provisional default**: a minimal internal actor
context (OS user + cell configuration), not a public identity API. If the owner
later defines a richer public contract, the internal fields are additive.

## Known traps

- The SFWP `Request` enum is the shared contract surface; every slice extends
  it. Land identity fields before idempotency (SF-006) to avoid re-editing.
- Keep inspect verbs identity-optional to preserve test and CLI compatibility.

## Definition of done

Every protected action carries resolved actor context, SoD is enforced
server-side, and the Workbench displays real identity.
