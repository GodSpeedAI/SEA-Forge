## Corrections applied during execution

1. **The Rust schema zero-diff step was already covered and is not repeated.**
   `crates/sea-forge-server/tests/conformance_sfwp.rs:625`
   (`generated_schemas_are_committed_and_current`) already regenerates the JSON
   Schemas and requires zero diff. Adding a second copy in `just` would have
   produced two gates that can disagree. The new recipe covers only the three
   genuinely ungated projections: TS/AJV, UI tokens, and the Tauri workspace
   boundary.

2. **`git diff --exit-code` alone is not a zero-diff check.** A new SFWP type
   generates a *new* file, which is untracked rather than modified, and
   `git diff` reports nothing. The gate pairs it with
   `git status --porcelain --untracked-files=all`.

3. **The token check runs through `bun`, not the `check-drift` npm script.**
   `packages/sea-forge-ui-tokens/package.json` declares
   `"check-drift": "node scripts/check-drift.mjs"`, and devbox pins no node
   toolchain for this repo — the `node` on PATH comes from the developer's
   mise install and would not exist in a clean environment. `bun` is already a
   hard dependency of this gate.

4. **`cargo metadata` needs `|| true`.** Removing the `[workspace]` table makes
   cargo exit non-zero rather than report a different root, and under
   `set -euo pipefail` that killed the recipe before it could explain itself.
   The empty result now falls through to the comparison and prints the fix.

## Completion evidence

`just workbench-contracts-gate` was run against each acceptance scenario. The
working tree was restored to clean after every probe.

| Scenario | Probe | Result |
|----------|-------|--------|
| Source schema drift | added a `driftProbe` property to `packages/contracts/schema/HelloResult.schema.json` | exit 1, "generated TS/AJV contracts drifted from the committed schemas" |
| New type not committed | copied a schema to `ZZDriftProbe.schema.json` | exit 1 |
| Token drift | appended a comment to `packages/sea-forge-ui-tokens/sea-forge.tokens.css` | exit 1, "sea-forge.tokens.css has drifted" |
| Tauri boundary removed | commented out `[workspace]` in `apps/desktop/src-tauri/Cargo.toml` | exit 1, "restore the empty [workspace] table … (ADR-004)" |
| Clean tree | no modification | exit 0, "ok: generated contracts, UI tokens, and the Tauri workspace boundary are current" |

One probe that deliberately does **not** fail, and why: hand-editing a file
under `generated/` passes, because the recipe regenerates the directory before
diffing and `scripts/generate.ts` rewrites it wholesale. That is the correct
semantic — the gate's claim is "committed output equals generated output," and
a hand edit that regeneration erases was never in the committed output. Drift
that matters originates in the *source*, and scenarios 1 and 2 cover it.

Not done here, per the packet: CI wiring belongs to SF-013. `workbench-check`
now depends on `workbench-contracts-gate`; neither `check` nor `ci` was
touched, so the kernel gate acquires no Bun dependency (K-06).

## Context

The Rust-to-schema gate works. The TS/token drift scripts exist but are not
invoked. The Tauri workspace boundary has no automated guard. A regression in
either can silently violate the kernel isolation invariant or the
contract-ownership invariant.

## Required outcome

One `just` recipe regenerates all projections and requires zero diff, plus a
boundary check that the Tauri workspace stays standalone.

## Current evidence

- `justfile:148-155` — `workbench-check` runs install/check/build/test, no drift.
- `check-drift.mjs` exists but is not called.
- `src-tauri/Cargo.toml` — empty `[workspace]`, no gate.

## Implementation boundaries

- Modify `justfile` only. Do not change generator scripts or generated output.
- CI wiring is SF-013 (CI changes require owner authorization).

## Acceptance scenarios

1. Change a `SCHEMA_TYPES` entry → `just workbench-check` fails on TS drift.
2. `bun run generate:contracts` → zero git diff.
3. Change `colors_and_type.css` without re-copying tokens → drift check fails.
4. Remove `[workspace]` from Tauri Cargo.toml → boundary check fails.

## Verification procedure

```sh
just workbench-check
just no-async-kernel
```

## Integration notes

Every later SFWP slice must pass this gate. SF-013 wires it into CI.

## Known traps

- `cargo metadata --manifest-path workbench/apps/desktop/src-tauri/Cargo.toml`
  is the most robust boundary check (it fails if the workspace resolves root
  members). A grep for `[workspace]` is simpler but less precise — prefer
  `cargo metadata` if it is fast enough.

## Definition of done

One gate catches schema, TS, token, and workspace-boundary drift deterministically.
