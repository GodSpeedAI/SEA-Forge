## Context

The Rust-to-schema gate works. The TS/token drift scripts exist but are not
invoked. The Tauri workspace boundary has no automated guard. A regression in
either can silently violate the kernel isolation invariant or the
contract-ownership invariant.

## Required outcome

One `just` recipe regenerates all projections and requires zero diff, plus a
boundary check that the Tauri workspace stays standalone.

## Current evidence

- `justfile:148-155` — `workbench-check` runs install/check/build/test, no drift.
- `check-drift.mjs` exists but is not called.
- `src-tauri/Cargo.toml` — empty `[workspace]`, no gate.

## Implementation boundaries

- Modify `justfile` only. Do not change generator scripts or generated output.
- CI wiring is SF-013 (CI changes require owner authorization).

## Acceptance scenarios

1. Change a `SCHEMA_TYPES` entry → `just workbench-check` fails on TS drift.
2. `bun run generate:contracts` → zero git diff.
3. Change `colors_and_type.css` without re-copying tokens → drift check fails.
4. Remove `[workspace]` from Tauri Cargo.toml → boundary check fails.

## Verification procedure

```sh
just workbench-check
just no-async-kernel
```

## Integration notes

Every later SFWP slice must pass this gate. SF-013 wires it into CI.

## Known traps

- `cargo metadata --manifest-path workbench/apps/desktop/src-tauri/Cargo.toml`
  is the most robust boundary check (it fails if the workspace resolves root
  members). A grep for `[workspace]` is simpler but less precise — prefer
  `cargo metadata` if it is fast enough.

## Definition of done

One gate catches schema, TS, token, and workspace-boundary drift deterministically.
