## Context

The final journey steps require the auditor to inspect complete records and the
operator to reuse accepted work honestly. The crates exist and are
component-tested but are not exposed over SFWP or rendered in the Workbench.

## Required outcome

An auditor sees source-linked, tamper-evident evidence with honest assurance.
An operator reuses accepted work without overstating what the evidence supports.

## Current evidence

- Evidence/settlement/capability crates exist, component-tested.
- No SFWP verbs for evidence/capability/memory/artifact inspection.
- CLI has `sea-forge artifact`, `sea-forge memory` but not over SFWP.

## Implementation boundaries

- Add read-only SFWP inspect verbs (additive, ADR-003).
- Wire EvidencePage to real records.
- Enforce conservative capability assurance.
- Do not build catalog breadth beyond the journey.

## Acceptance scenarios

1. Evidence inspection → source-linked, complete.
2. Tampered ledger → halt.
3. Insufficient evidence → conservative capability.
4. Disclosure denial → unsupported not retrievable as proven.
5. Reuse → accepted work becomes capability/artifact honestly.

## Verification procedure

```sh
cargo test -p sea-forge-evidence
cargo test -p sea-forge-settlement
cargo test -p sea-forge-capability
cargo test -p sea-forge-server sfwp
cd workbench && bun run check && bun run test
```

## Integration notes

SF-012 (packaged E2E) proves this slice on a real distribution. The SFWP verbs
added here extend the `IMPLEMENTED_METHODS` table and generated contracts
(SF-007 gate applies).

## Known traps

- The SFWP enum/schema registry is a shared barrel; every slice extends it. Run
  the generation gate (SF-007) after adding verbs.
- Capability assurance must fold ALL evidence (including denial/timeout), not
  just the successful path.

## Definition of done

The representative journey completes through evidence inspection and honest
reuse, with no overstated assurance.
