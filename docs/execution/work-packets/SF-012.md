## Context

The components are tested in isolation. No proof exists that they form a usable
product on a clean host. The mocked Playwright harness cannot honestly prove
real IPC, settlement, or recovery.

## Required outcome

A clean Linux host installs the packaged product and completes every
representative scenario through the real stack, with accessibility and restart
proofs.

## Current evidence

- `playwright.config.ts:3-9` — mocks `__TAURI_INTERNALS__`.
- `e2e/tauriMock.ts` — mocks all IPC.
- No packaged install procedure.

## Implementation boundaries

- Replace the mocked harness with a real-server E2E config.
- Build and inventory the Linux package.
- Do not mock IPC in the E2E path.
- macOS is secondary: mark "not run" until Seatbelt passes.

### User-decision checkpoint (U-06)

If the owner selects Tauri sidecar supervision, the host gains process-spawn
wiring for the server binary. If the default (separate service) stands, the
E2E harness starts the server externally. Either way, the scenarios and
acceptance criteria are identical.

## Acceptance scenarios

1-12. The 12 scenarios from `PRODUCT_COMPLETION_DEFINITION.md` "Primary User
Journey."
13. Accessibility scan passes.
14. Bundle has no Bun.
15. Restart mid-work → valid prefix + recovery.

## Verification procedure

```sh
cd workbench && bun run tauri build
cd workbench && bunx playwright test e2e/ --workers=1
```

## Integration notes

SF-013 (release) gates CI on this E2E and produces checksummed artifacts. This
packet is the final integration checkpoint before release.

## Known traps

- The real-server E2E must use a temp cell root, not the developer's cell.
- Tauri capabilities (CSP, permission scopes) must permit only required local
  actions — audit before packaging.
- macOS Seatbelt must be exercised, not assumed, before advertising support.

## Definition of done

A clean Linux host completes the full representative journey through the real
packaged stack, with accessibility, restart, and bundle-inventory proof.
