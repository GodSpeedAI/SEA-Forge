# contracts/generated

## Overview

This directory is a **generated zone**. It contains no hand-written source: every file here is emitted by the SFWP contract generator at `../scripts/generate.ts` from the Rust-emitted JSON Schemas in `../schema/*.schema.json`. For each schema `Name.schema.json` the generator produces:

- `Name.ts` — a TypeScript interface compiled by `json-schema-to-typescript` (interface name taken from the schema `title`).
- `Name.validator.ts` — a precompiled AJV 2020 `ValidateFunction<Name>` emitted via `ajv/dist/standalone`, so the packaged renderer validates trusted server responses without `unsafe-eval` under its strict CSP [scripts/generate.ts:main].
- `index.ts` — a barrel re-exporting every type (`export type { N }`) and every validator (`export { validate as validateN }`) [generated/index.ts].

The 64 schema names (hence 64 types and 64 validators) cover the SFWP surface consumed by the Workbench renderer: case/run lifecycle (`CaseSummary`, `CaseOverview`, `RunRecord`, `RunSettlement`, ...), approvals and delegation (`PendingApproval`, `DelegationPreviewResult`, `ApprovalGovernanceContext`, ...), evidence and integrity (`EvidenceRow`-adjacent views, `RecordDigest`, `SourceRecordRef`, ...), readiness/preflight (`ReadinessView`, `PreflightParams`, `PreflightResult`, ...), and misc transport results (`HelloResult`, `DescribeResult`, `GetSchemaResult`, `UnsupportedVersion`).

**Never hand-edit anything in this directory.** Regenerate instead (see Verification).

## Interface

- `export type { <Name> } from "./<Name>.js"` for every schema in `../schema/` — barrel in [index.ts]
- `export { validate as validate<Name> } from "./<Name>.validator.js"` — one precompiled validator per type, typed `ValidateFunction<Name>` [scripts/generate.ts:main]
- Package entry point: `.` maps to `./generated/index.ts` [package.json:exports]
- Example: `export interface CaseSummary { case_id, case_state, close_reason?, closed_at?, created_at, run_count, summary }` [generated/CaseSummary.ts:CaseSummary]

## Invariants

- Byte-identical regeneration: output is deterministic (sorted schema files, timestamp-free banner, stable ordering) so running the generator twice with unchanged schemas produces an empty diff [scripts/generate.ts:BANNER].
- Files are rebuilt from scratch each run; deleted schemas leave no stale outputs [scripts/generate.ts:rmSync].
- Every generated file carries the banner `AUTO-GENERATED by scripts/generate.ts ... DO NOT EDIT` [scripts/generate.ts:BANNER].
- Validator files use `// @ts-nocheck` and carry an explicit `ValidateFunction<Name>` annotation on the single `validate` export [scripts/generate.ts:main].
- `additionalProperties: false` is enforced on compiled interfaces [scripts/generate.ts:compile].

## Side Effects

- Only at generation time (via the generator in `../scripts/`): deletes and recreates this directory (`rmSync`/`mkdirSync`), then writes `Name.ts`, `Name.validator.ts`, and `index.ts` [scripts/generate.ts:main]. At import time the generated modules are pure: they perform no I/O, network calls, or process-level mutations (validators execute compiled AJV code only).

## Verification

- Run: `just workbench-contracts-generate` — regenerates this zone; `just workbench-contracts-gate` — fails if `git diff --exit-code -- packages/contracts/generated` is non-empty or untracked files appear [justfile:workbench-contracts-gate].
- Direct equivalent: `cd workbench && bun run generate:contracts` (wrapper for `bun run --cwd packages/contracts generate`).
